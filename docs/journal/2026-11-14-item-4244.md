## The mechanism

`BuildTypeData::find_gather_tcoords@0063bdc0`'s metal branch is the only writer that is not a reset. With `mtn` and
`cliff` both negative it asks `MountainsData::find_nearest` and `CliffsData::find_nearest`. On the range arm, inside
`gather_radius · 0xc0`, it stores `mtn` (`:146`) **before** walking the tiles; the cliff arm stores `cliff` (`:196`)
the same way. With one already set it reuses that index at distance 0 and stores the same value again. The resets
are `MiningList::MiningList` and `MiningList::clear` (−1, −1), and `Build::close`'s `+0xb4 = 0xffff` (`:555`,
printed as a `Leaders` field by the decompiler). `MiningList::clear`'s other callers are `calc_gather`'s stack
locals, not a building. The only building caller of the fill is `Build::find_gather_tiles@00623350`.

In the crate, `Sim::note_mine_source` runs in `find_gather_tiles` ahead of `gather_tcoords`. For a metal type with
neither field set it stores what `mine_arm` picks: the range's placed index, or the cliff's. `give_back_gather_tiles`,
`Build::close`'s tail, resets both.
