## Step 2: the chapter, before the capture

- **The DLL's third half.** An `@` line in `rontrace.cmd` is an issuer
  line, not a cheat. `tools/trace/tracer.c`'s `issue_line` runs `@move <who>
  <x> <y> <o>…` through `issue_move_to`. It refuses by `INFO` 17 (a refusal
  code in `b`'s high half) on a bad prologue, on a `who` that is not the
  console's player, on an object that is not a live captain of `who` with
  that id, or when the package has no room. Each issued object is an `INFO`
  18. It compiles `-Werror` both plain and under `RON_AUTOSTART`.
- **The command's entry into the sim** is `crate::input::group_move_to`:
  `process_group` + `process_move_to` → `Group::action_move_to`, with the
  action bit, on a forced `push_group`. The recorded-game stream's own
  `MoveTo` (`input::Stream`) still gives each unit an `add_move_order` and
  bypasses the group. I did not change it, because run7's tests pin its
  counts. It is reported below.
- **`crate::golden::Script` defers an `@` line one frame.** The pump
  processes the command after `do_frame` and before the next one, so the
  line runs before the tick of F+1, ahead of that frame's cheats.
- **The staging.** I found a SANDY lake (region 65, cells x 7–11, y 7–17)
  between the chariot's seat and its point by rendering run175's start
  `WORLD`. The chariot's plan must bend round its north end. The squad's
  first destination took it round the same lake and past 1100, so I
  re-sited it down the west shore before committing.
- **This crate's prediction**, from a scratch walk stood up from run175: the
  chariot gets a plain `MOVE_TO`, an 11-entry plan, and arrives on block
