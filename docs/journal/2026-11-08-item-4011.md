How it was done. A scratch script did the work; it is not committed.

- **A file named as its directory** becomes that directory's `mod.rs`: `world.rs` → `world/mod.rs`, and the same for
  `mapgen`, `territory`, `vision` and `movement`. Its siblings are declared at its end, so its module path, its tests'
  names and its line numbers all hold. The other directories got a two-line `mod.rs`.
- **`lib.rs`'s `mod f;` lines** become the shim, one line for one line. A line like `pub use self::world::danger;`
  takes `danger`'s line. In a new directory, the first file's line becomes `pub mod core;` and the second file's line
  becomes the grouped shim `pub use self::core::{flag_reads, tuning};`. **`lib.rs` stays at 8,252 lines**, so no
  `lib.rs:N` citation moved. `cargo fmt` re-sorts the new `pub mod` lines inside their run and adds no lines.
  `crate::danger::…`, `sim::danger::…`, the `SITE_*` constants and the sweeps' paths all resolve through the shim,
  which item 4017 deletes.
- **`core`**: a module of that name compiles beside the `core` crate. The one `core::array::from_fn`, in
  `mapgen/mod.rs`, resolves to the crate, because a path inside a submodule never sees the root's names. The shim
  spells `self::core::` so the `use` is not ambiguous.
- **What the source said, before the first move.** The 75 files and their test files contain no `module_path!`,
  `file!()`, `line!()`, `type_name`, `include_str!`, `#[path]`, `pub(super)`, `pub(in …)` or `macro_rules!`. The only
  production `super::` is `mesh.rs`'s inner `mod tables`, which is still `mesh`. So no output a test matches changed.
- **Citations.** `paths.py move` rewrote 875 citations across the ten moves. One citation did not follow:
  the bold citation of `supply.rs`'s old path in `docs/audit/2026-08-20-supply.md`. The regex reads the bold `**` as a glob, so the
  rewrite missed it, and I mended it by hand. `--check` now lists only the 12 pinned citations. The five bare
  `sim/src/<file>.rs` mentions are in dated journals (items 1740, 1776, 1988), and I left them as written.

## What the move would have broken, and the fix in each reader

- **`rondata::writers`.** `read_sim` and `three_views` read the flat `src/`, and the sibling test files one directory
  down. They would have lost 75 production files without failing. They now share `sim_files()`: a recursive walk that
  leaves out `sweep/` (read on its own) and `test_support/`. A nested `*tests.rs` is test source; any other file is
  production. One change in what is read: `do_attack/live.rs` is production that the flat walk never reached, and now
  it is read. `writers::` passes.
- **`rares::tests::a_unit_s_speed_is_never_set_from_the_raw_moves`** read the flat `src/`. It is now recursive (but
  `sweep/`) and skips `*tests.rs` files, which are no spawn site. On the first run it failed on its own body at
  `rares/tests.rs:1058`; that was the reason for the skip. It passes.
- **`nations::tests::sim_sources`** and **`tools/nations_census.py`** key the sources by file name for
  `docs/NATIONS.md`'s "modelled at" rows. A `foo/mod.rs` is now `foo.rs`, and a sibling test file is its module's at
  any depth (but `sweep/`). `nations::` passes, and `nations_census --check` reports `the round trip is empty`.
- **`tools/recomp/fit_bay.py`** builds `launch.rs`'s path from parts, so `paths.py` could not see it. It now goes
  through `data/`.

**The readers that need no change**: `no_float::module_tree` (the float scan and `docs_guard`'s test-file list),

- `nations_census --check`: empty.
