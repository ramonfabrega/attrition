## The fix

- `Sim::init_ceo_mask` (`economy/holdings.rs`) sets or clears `umask2::CEO_BIT` by `speed_is(u, 0x165, true)`, which
  is `TypeData::is` strict: the type itself, or a nation's graft of it that is not unique. When the bit is set, it
  calls `update_ceo_position(u, None, Some(tile))`. The birth path calls it beside the marine mark
  (`init_iroquois_masks`). The harness's start dumps reach it the same way.
- The set_type adapter answers `is_ceo` with the same predicate. It seeds its `+0x6c` word from the unit, writes
  the CEO bit back (set and clear), and runs `update_ceo_position` from nowhere to the unit's tile.
- `has_ceo_bit` reads the bit. The crossing test's fixture sets it by hand, because its tree carries no 0x165.
- `go_inside` and `come_out` still do not call `update_ceo_position`. That remains a SEAM, named in the doc comment
  and in `docs/RECGAME.md`'s "Not established".

**Test.** `row_105_s_ceo_carries_the_ceo_bit_from_its_set_type_on_run1752_s_ranges` (`diff::held_out`) compares
every units range on 2982 and 2983, ours against theirs, byte for byte. It also names `1/17`'s TI (0x163, then 0x165)
and theirs' `unit_masks2` (0, then 0x10000). **Mutation**: `tools/mutate.py --edit
