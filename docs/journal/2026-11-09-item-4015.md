order types and the move-order constructor went to `order`. The list, the enqueues, every `add_*_order`, the strafe and

**How.** A scratch script, not committed. It cuts at item boundaries, at the top level and inside `impl Sim`, with a
small lexer that skips strings, raw strings and comments. It writes each piece as a child of the file's module:
`//!` line, `use super::*;`, the top-level items in their order, then one `impl Sim { … }`. Children, not siblings,
because that keeps privacy exact. An item private in the parent reaches the parent and its descendants, the sibling
test files among them, and `pub(super)` in a child reaches exactly that. So 127 + 60 + 45 items, methods and struct
fields were raised that way. `pub` and `pub(crate)` stayed as written. Each child is re-exported by glob (`pub use
self::order::*;`), so every `crate::orders::x` path `rondata`, the sweeps and the tests name still resolves. A child
holding only `impl Sim` methods takes no glob: `stats`, `acquire`, `projectiles`, `pool` and `actions`, and `think`
outside tests, since its two steps are named only by the sweeps. An unused glob warns. One line in each parent says so.

**Verbatim.** For each piece, I put the base's chunks in the order the script writes them beside the new file, with
`pub(super)` removed. All sixteen are **token-equal** once whitespace is ignored. `diff -w` is **0 lines** on twelve of
them. The other four total 30 lines (`order_list` 7, `attack` 8, `delivery` 8, `acquire` 7), and they are all one
thing: four signatures that `pub(super) ` pushed past the line width, which rustfmt rewrapped (`strafe_attack`,
`siege_ground_arm`, `take_damage`, `mark_contact`). No statement moved inside a function, so the rng stream is the
base's.

**One slip, caught.** When I rewrote `fight.rs`'s new tail, rustfmt had already sorted `#[cfg(test)] mod tests;` in
among the new `mod` lines, and I cut it off with them. The lib test then flagged two `#[cfg(test)]` methods as never
used. That is how I found it. The mount was restored before the commit, the warnings went with it, and the test list
below is the check.

**Names.** `order_list.rs`, not `queue.rs`, because `cities/queue.rs` exists and the census keys a file by its bare
name. `delivery.rs`, not `damage.rs`, because of `combat/damage.rs`. `moving.rs`, because `move` is a keyword. No new
file shares a bare name with another under `crates/sim`.
