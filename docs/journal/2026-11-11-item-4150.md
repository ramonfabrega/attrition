## Step 2: the writers, by both nets

- **The export** (`->block`, and `0x18 + … field_0x134` on the left of a store): `WData::WData`
  and `~WData` (0); `World::close` (frees every block); `GameDaemon::process_coll_blocks` (frees
  one); `World::new_coll_block` (allocates); `World::walk_data`'s restore arm (allocates by the
  saved presence); and `UnitBalance::next`, a balance tool that does not run in play.
- **The listing**: of the `0x18(%r,%r,4)` stores in functions that load `0x134(`, only
  `new_coll_block`'s is the world's. Its callers in the listing are `Object::add_to_world`,
  `Guy::process` and `CollCheck::move_unit`, and nothing else. `CollBlock::set` is called from
  `Objects::kill_guy`, a clear. No writer stores the `-1` that the allocators test for.
- **Allocation**: all three allocators call `new_coll_block` only on a set into a null block,
  then store the bit and state 0. Clears skip a null block. `move_unit`'s one-block form returns
  on a null block.
- **Freeing**: `process_coll_blocks` runs from `GameDaemon::process_all` after `check_borders`.
  It visits `max(5, xs / 4)` cells from `GameDaemon.empty_colls`. It frees a block when the state
  is odd, keeps state 0, and for state 2 ORs the body: some bit set means state 0 and keep, none
  means free. The decompile shows a `= 1` falling through to the delete, and the listing
  settles it: `movl $1, 0x8(%edx)` at `732019`, then the delete at `732020`. `CollBlock::set`
  stores 0 on a set and stores 2 on a clear of a state 0 block, so the verdict reduces to the
  body. `GameDaemon::init`, `close` and `World::close` zero the cursor.
