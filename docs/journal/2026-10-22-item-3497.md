## The header difference, and who reads it

3484 found that `cmp` is never 0 on the raw files. Re-read here on all six takes, everything before the first
` BEGIN FRAME` (113, 113 and 134 lines) differs only on these lines:

```
3c3   … TURN_CONTROL 3924  |  … 2365
5c5   … LOADING WINDOW SYNC 3930  |  … 2372
12c12  Sys Memory 6094850  |  Sys Memory 462848002
```

That is the two `SYNCPOINT` load timings and, on some takes, `Sys Memory` and `CPU speed`. 3484 showed they differ
between any two takes whatever the pref.

**The parser ignores them, read from the code.** `rondata::gamelog::Log::parse` → `fill` puts every line before the
first `BEGIN` into `Log::preamble` as a `(first token, rest)` field (`gamelog.rs`, the `None =>` arm of the stack
match). These lines become `("SYNCPOINT:SYNC", "ENTER. … 2620")`, `("Sys", "Memory 6094850")` and
`("CPU", "speed 999")`. `preamble` has one reader in the crate: `Log::checksums` → `checksums_in`, which matches
`CHECKSUM`, `FILE`, `LINE` and `game_random` only. No other crate reads `.preamble` (`git grep -n '\.preamble\b'`:
only `gamelog.rs`, and `ledger.rs` names it in a comment). Nothing in `crates/` or `tools/` matches `SYNCPOINT`,
`Sys Memory` or `CPU speed` by name.
The oracle's `schema()` (`crates/rondata/src/diff/oracle.rs`) does not read a gamelog at all. It hashes the
**parser's sources** (`SCHEMA_SOURCES`, through `keyed`) to key the cache generation, so a header line cannot reach it.
The test added here only changes what `keyed` skips (`mod tests`), so it does not turn a generation over.

**Pinned as an assertion**: `gamelog::tests::the_header_lines_two_takes_differ_on_reach_no_reader` parses two
texts that carry run1103's and run1104's header values around a `CHECKSUM` record and the sample game. It asserts
that the lines are read (as preamble fields), that `checksums()` agrees and holds the record, and that every block
spells the same. Made to fail first: a header difference a reader does see (`LINE` 1 against 0 in the record) fails
it, `left: [Checksum { … line: 1 … }]`, `right: [… line: 0 …]`.
