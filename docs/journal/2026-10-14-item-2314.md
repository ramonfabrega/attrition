**Behaviour changes:**
- **One, in `update_gpiece`.** The port re-pieced every figure in `0..guys.len()`. It now bounds the crew by the
  type's `crew_size`, as the original does. The set is the same in play, because the stack is built as `crew_size +
  SQUAD_SIZE`. Two `anim` tests had hand-built two-figure units on a type left at `crew_size` 0, and now set it to 1
  (`an_unpack_puts_a_trackless_crew_figure_on_its_leader`, `an_unpack_puts_a_tracked_crew_figure_on_its_new_offset`).
- **No others in answer.**
  - `is_in_range` gates `big_radius` per unit (a building's loaded `big_radius` is 0).
  - `add_think_order` bumps `new_head` after `clear_partial_path` rather than before; the two write unrelated fields.
  - `combat::in_range` is no longer called by the port; it keeps its own unit test.

**Not taken, and why:**

  possible divergence: `spot_sweep` reads the radius from `profile(Obj::Unit(u))`, where the original reads the type
  at `this+0x18`.
- **`Object::adjacent_to`**: the port lacks the boat-garrison arm and both in-use guards (parked 2315).
