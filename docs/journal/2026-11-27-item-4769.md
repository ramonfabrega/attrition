## The reading

`Unit::swap_team@006118d0`, the per-figure do-while:

```text
new.flags = new.flags & 0x40 | old.flags & 0xbf          :58, :63
if !(new.flags & 1):  Object::remove_from_world(new)      :72
else:                 set_new_location(new, old.x, old.y, 1, 1)
per guy: +0x9d, +0xa2, +0xc..+0x18, +0x20..+0x40 copied  ; not +0x1c
```

`Object::remove_from_world@00647970` gates its disc walk on vslot `+0x8`, which is `SubObjectData::is_active@0046cda0`
(`flags & 1`). That bit is clear here, so only the chain half runs (`:113`..`:162`). It writes nothing to the flags
byte. On the set arm, `param_4 = 1` is `set_new_location`'s turn: `Guy::set_angle(guy 0, unit angle, 1)` writes guy
0's `angle` and `last_angle`. The per-guy loop comes after, and it copies `+0x18` (`angle`) but not `+0x1c`
(`last_angle`). That accounts for `2/40`: theirs' `last_angle` is −1191444480, which is the unit's `angle` (`+0x50`,
copied on both sides). Ours had called `set_new_location` with no turn, so its `last_angle` was still `init`'s
0x55555555.

Ours walks a unit on the units line exactly when it is `alive()` (`unit_flags_byte` always sets 1). So the
original's `flags & 1` is ours' `alive()` on the old figure.
