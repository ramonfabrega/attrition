# Item 487 — the widening killed the brief's own successor, and the word moved 33

*2026-09-22, worker lane, Opus 5. `docs/ORDERS.md` §20 written, §19.3
amended.*

The brief was unusual and said so: 10245's eleven value rows and the
word's extra draw both named `1/27`, without anyone asking them to. Two
instruments agreeing unprompted has been rare in this chain, and the
brief called the framing better supported than usual while still telling
me to re-measure it. That was the right instruction, and it is the whole
story of the item.

## What the widening said

One run of `run100_s_word_block_is_every_record_the_dump_carries` with
`RON_DEBUG_ROWS=10236-10250`, five seconds, before a line changed.
`1/27`'s block was exactly as booked. The *successor* 483 had named was
not.

483 wrote: "`1/29` drops its move order on block 10241 — `order:kind`
ours 10 theirs 1, `path:length` ours 0 theirs 43 — and stands 28 units
short in `x`."

Kind 10 is `ATTACK` and kind 1 is `MOVE_TO`, and `orders_front_first` is
the log's list **reversed**. So the row says this crate is still holding
an attack where the original is already on the move underneath it — the
opposite subject. And `RON_DEBUG_UNIT=1/29@10237-10248` settled the rest
in one more run: this crate's `1/29` stands at `(4680, 29928)` on every
block of the window with an empty path. It does not stand *short*. It
does not move *at all*.

The frame was right. The mechanism was 180 degrees out. That is
`docs/DECISIONS.md` 42 for the fourth time in this chain, and it cost
twenty minutes to find rather than an item to chase.

## The raw record is what named the mechanism

`track.py` and a small `BEGIN`-structure dump of run100's own `UNITDATA`
for `1/29`:

```
block 10240   [ GroupMoveOrder(19) …, ATTACKORDER(10) ]   path 1 node
block 10241   [ ATTACKORDER(10), MOVEORDER(1) ]           path 43 nodes
```

Two orders on both blocks, the same two, and the order between them
swapped. A push cannot do that and a pop cannot do that. `Unit::
ungroup_move_order@005fd140` can: its `GROUP_MOVE` arm builds a **new**
plain `MoveOrder`, `remove_current`s the old node and calls
`LinkListBase::add` — which prepends. The conversion is a promotion, and
this crate rewrote the order where it stood.

Promoting it was not enough: the move then died on the same frame. A
`#[track_caller]` probe on `kill_current_order`, and then on `repath`,
named the killer in two runs — `do_move`'s dead-target arm. The
decompile of that arm ends in a bare `repath(this)`, but the listing at
`0x5f8221` has a `vector_dist` against `0x480` above it that the
decompiler had lost the arguments of (`unaff_EDI`), and `MoveOrder +0x4`/
`+0x8` in the type record say what `edi` was: the move's own destination.
`1/29`'s is 28,000 units away, sixty times the gate.

Two mechanisms, both listing-backed, neither guessable from the prose.

## The numbers

Word **10244 → 10277**, count and sequence together. run53's frames on
the original's count 11,922 → 12,059 and draw for draw 10,509 → 10,651.
Great Lakes' endpoint `off` **51 → 42** with `unlinked` unmoved. Block

The new word is the same shape one raider over: `1/40` colliding with
`1/41`. Its block also carries two `half_step` rows — the original sets
the soft-collision one-shot on both units and this crate on neither — and

arrow between it and the hard collision is the successor's to establish.
Writing it as a mechanism is precisely what put this item's brief wrong.

## What went wrong on my side

One self-inflicted wound worth recording. I chained `git checkout
crates/sim/src/orders.rs` onto a decoy-patch command whose `assert`
failed first — so the patch never ran and the checkout reverted both real
changes. `git diff --stat` caught it within a minute and the two patch
scripts in the job's tmp dir replayed it exactly, which is the argument
for writing patches as scripts rather than as inline `sed`. **Never put a
`git checkout <file>` in the same command as an edit that can fail.** The
restore-from-copy pattern used for the rest of the decoys (`cp
orders.rs.good`) has no such failure mode.
