## 2026-09-17 — item 319: the scout's danger term, routed to zero (Opus 5)

Great Lakes' word stood at **8030** and moved to **8031**. Small, and the
reason it is worth the file is what was behind it: a seam whose own comment
said it could not be closed, and the comment was a claim about this crate's
code rather than about the original's.

what a danger map is.

**And the term was there all along.** `docs/SCOUT.md` §8 has had
`score += danger[who][(wy >> 1) * reg_xs + (wx >> 1)]` in the formula since
the document was written; `Sim::scout_danger` returned `0` behind

> keyed differently from `World::danger`, so it is not routed there.

Both halves wrong. `World::danger_half(who, c)` is `(c.y / 2) * reg_xs +
(c.x / 2)`, the listing's shift exactly, and the grid behind it is diff-backed
**value for value** — all 7,200 — against run64's own `danger[who][scan]`
(`docs/DANGER.md` §8). The seam was the routing and nothing else. The fix is
one line.

I read the listing rather than the decompiler for the two call sites,
because Ghidra renders them as unrelated pointer walks: `sarl` on each cell
coordinate, `imull 0x24(%ecx)` for `reg_xs`, the row at `0x13c(%ecx,who,4)`,
then the load and the `addl` that carries the not-mine four — `005f66d2` in
the city loop and `005f6b45` in the region scan, the same five instructions
twice. The region scan's is unreachable for an AI scout (§11's `local_74`),
so the city loop's is the one that moved the word.
