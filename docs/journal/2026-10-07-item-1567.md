### (a) The lane gate without the full suite

**The design.** `tools/release_gate.py --lane` now requires `--tests
FILTER …` — the word's own tests, named by the brief — and its release
step passes `--exact` and one `--skip` for every rondata test the timings
file (`docs/audit/2026-10-06-suite-timings.txt`, every test alone) times
over `LANE_BUDGET_SECONDS` = 1.0 that no filter names: 463 of 771 tests,
2,550 of 2,606 CPU seconds. Everything else runs — the sim suite whole
(2 s), the data layer, the paperwork (`diff::floors`, `the_handoff`), the
308 rondata tests under a second, and any test the file does not name (a
worker's new widening runs without being asked). A filter that matched no
test that ran turns the gate red (`unmatched_filters`, read off the log's
`test <name> ... ok|FAILED` lines), so a typo is not a pass. The two
coverage pins (118 s and 80 s alone) are over budget and so the booking
gate's, unless a word passes `--tests coverage::`. `--tests` without
`--lane` refuses: the booking gate takes no flag and runs everything.

Why a budget over the timings rather than "the word's tests only": it is
one cargo command, so the step list, the log and the lane verdict are
unchanged; a new test runs by default; and the sim suite and the data
layer — cheap, and what a sim change breaks first — stay in.
`libtest`'s `--skip` honours `--exact` (checked on the release binary:
one exact skip leaves 770 of 771, `--skip diff::coverage` with `--exact`
skips nothing), and the full skip list leaves 308 tests, none untimed on
this tree.
