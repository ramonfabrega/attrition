# Item 3484 — the gamelog's console mirror off, byte-identical (2026-10-22, `att-3484`, Opus 5.5)

A `coverage` lane of the fifty-first tranche, on the click-free pool, base `62a2035f`. It measures one setting
(`rise.ini` `AllowLogs_ToConsole`, staged by the runner's `--console-log 0`, item 3483). No simulation change, no trace
pinned, `blind::` does not move. The pool's default is unchanged: the flip stays opt-in until a pass flips it.

**The result: with the mirror off, the dump is the same bytes and the draw stream is the same on all three lobbies,
and a dumped frame is 30–37× faster.** Nothing in the tree reads the mirrored text, so the default can flip without
any tool going blind.

## The formatting share, and what it means for the writer

With the mirror off, `String::printf` is never called: it only fed `OutputDebugStringW`. What is left of a dumped
frame is mostly the CRT's two imports. `__stdio_common_vfwprintf` and `fputwc` take 0.047, 0.058 and 0.060 s of the
three frames, which is **75, 68 and 66 %**. `Log::say`'s own code is 0.006–0.008 s, `WriteFile` 0.003 s and the
walkers 0.002–0.003 s. So the booking's condition is met as a share: more than a fifth of the frame is still in the
formatting. As seconds, though, the most a byte-identical writer could save is about 0.05 s a dumped frame, against
the 2.6–3.2 s the pref already removes. That is parked 3484a, for the steer. Nothing is built.

## Lane 1's 32-frame stall (parked 3484b)

The team take with the mirror off (run1107) took 69.6 s, against 53.8 s for its twin. The window is not why. Its
frames outside the window add up to 54.2 s against 24.6 s. The difference is 37 frames of about 0.9 s each, on every
32nd frame from 239. run1105 has eleven such frames. Both mirror-off takes ran on lane 1, so lane and pref could not
be told apart. One swapped scratch pair was run on the cheap lobby to separate them: run1105b and run1106b, not
filed, with the default take launched first so that it took lane 1. run1105b (off, lane 2) takes 14.9 s with no slow
frame after 0. run1106b (on, lane 1) has the stall on 223–415. **So the stall goes with lane 1 and an AI-on lobby,
not with the pref.** The two golden-start takes (AI off) have no stall. The cause is not read.

No tool in the tree does that.

## For the Loop

The flip is safe to make the pool's default. On three lobbies the dump is byte-identical after the header and the
draw stream is identical, nothing in `tools/` reads the mirror (`WINEDEBUG=-all` already discarded it), and a dumped
frame goes from 2.7–3.3 s to 0.06–0.09 s. Whether it flips is a pass's call. A separate finding: pool lane 1 stalls
about 0.9 s every 32 frames in AI-on lobbies (parked 3484b).
