## 617, and the widening named the record in one run

The first walk parted at 617: ours 6 draws, theirs 8, led by
`Guy::set_anim+0xf2f < Guy::move+0x166`. The trailing `Farms` draw was the
value shift. The widening printed both sides of block 617. Both hold
`1/6` attacking `0/6` from the same seat. The original faces `671481856`
and this crate `−402259968`. The second is the true bearing, and the first
is the bearing plus exactly a quarter turn.

The listing had the rule, and `fight.rs` already named it as a seam in
`swing_anim`'s comment ("the sideways flag … this crate does not model
that offset"). `Unit::fight@005fd4d0:698–714` takes the bearing ±
`0x40000000`, whichever is nearer the current angle. It applies to a type
with `g`, unless the attacker is a Patrol Boat and its target is at sea,
and `set_angle` applies it at once. The dump's 63.7° one-frame turn is
exactly the nearer side from a 120° heading. `0/6` does the same on 635
from the other end and lands on the same angle.

It was small and it was the word's own cause, so I took it:
`Sim::attack_angle` and `uflags::SIDEWAYS`. The swing's rocking arm now
reads the direct bearing against the offset heading, as the listing does.
The word moved to **621**. The widening was made to fail once with the
rule reverted. The four `1/6` angle rows came back on 617–618, and the
unit test carries run127's own numbers.

A side correction, in the same comment: its "a **target** of type
PATROLBOAT" misread `local_20`, which is the attacker's own type index,
written at `:609`. No behaviour depended on it, because that arm is not
