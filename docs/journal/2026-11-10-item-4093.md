   never bumped (`:310`), so each call writes its whole region row-major. The per-cell goods scan (`:620`–`:660`)

   `new_rare` then `ever_seen |= 1 << p` once `seen2[2cy+1][2cx+1] & ally_mask` (or `p > 7`, `reveal_map 3`,
   `0x800`, `+0x59e4`). Setup calls it from `Setup::build_cities@005ab910`, after each city's `update_seen_ally`,
   and from `build_game@005ac190:883`. The `:1071` call is the conquest setup script's. The other thirteen callers
   are the scenario editor, scenario import, conquest, and three scenario-script functions no AI script calls.
2. **Why oil alone.** `git log -S claim_oil_from_owners`: item 1505 wrote it for the oil patches, before the
   territory scan had a rare arm here. Item 1555 built the rare arm in play and left setup oil-only on purpose,
   because the installed start's fog replay stood in (`docs/AI.md` §152). The built start came later, took the
   setup recompute as it stood, and has no fog replay. The reason still holds for the installed start, so that
   path is left alone.

   with a bit. The original: run9's `[Start Game]` prints good 15 `ever_seen 2` (the dump's `GOOD` records do carry

   prints leader 1 `known_rares 1` and `reg_known_rares[scan]` 1 at index 1.
4. **Where in our setup.** `sync_territory(); settle_borders()` is this crate's `compute_all_territory`, and the
   built start calls it at exactly `build_cities`' and `build_game:883`'s points (start.rs). Before play,
   `settle_borders` found no pass and did nothing. It now runs the rares' half there. The installed start
   (`build_sim`) never calls `settle_borders`. Placing the scan in `start_border_pass`'s pre-play arm instead
   would also have reached the installed start's activations, over the dump's installed fog.
5. **The port, the tests, the floors, the documents.** A sim unit test of the scan's order and gates; the goods
   test turned to the line's own; a frame-0 test against run9's `GOOD` records; `CHECKSUM_STATE` re-pinned. Each
