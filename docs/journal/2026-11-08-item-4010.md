# Item 4010 — the in-file tests move to siblings

Opus 5.5, lane A, base `dcc465143`. One session. A `structure` item (`docs/STRUCTURE.md` §5, move 3). No capture,
no packet, nothing under `tools/emu`. **No behaviour change**: no production line of `crates/sim` was edited or
reordered. Each test module became its own file, and the place it stood now holds a two-line declaration.

## The move

A scratch script did the work; it is not committed. It used `tools/shape.py`'s own `tail_blocks` and `test_mounted`, so
it walked exactly the blocks the `test-tails` count reads. That is **112 inline `#[cfg(test)] mod NAME { … }` blocks in
100 production files** of `crates/sim/src`, all at the root. For each block:

- the body went to `foo/NAME.rs`, dedented four spaces (97 `tests.rs`, 15 named ones: `air/launch_tests.rs`,
  `air/flak_tests.rs`, `air/infantry_step_tests.rs`, `anim/survivor_tests.rs`, `cast/decoy_type_tests.rs`,
  `combat/table_tests.rs`, `production/infinite_tests.rs`, `scout/unit_bit_tests.rs`, and `orders.rs`'s seven);
- the block became `#[cfg(test)]` plus `mod NAME;` **at the same place**, with any attribute or comment lines that sat
  between kept;
- the dedent skipped any line that starts inside a string literal. A small lexer tracked strings, raw strings, char
  literals and nested block comments, so no literal's bytes changed. `cargo fmt` did the rest.

The script asserted its shapes as it went: each header was exactly `mod NAME {`, each close was a bare `}`, and no target
file already existed. All 112 passed. **`orders.rs`, `air.rs` and `cast.rs`**, which carry production code after a test
module, did not need cutting by hand in the end. Each of their modules became its declaration in place, so the
production code after it is byte-for-byte what it was, in the same order. Only its line numbers shifted up. The rng
stream cannot see a test module.

Nothing else in a moved body needed changing. No tail used `include_str!`, `include_bytes!`, `#[path]`, `file!()` or
`line!()`, so the new directory changes nothing a test reads. `super::*` resolves as it did, because the module nesting
is the same.

**Test names are unchanged.** Before and after, `cargo test --release --workspace -- --list` gave 5,808 tests each. The
diff of the sorted lists has **0 test lines**; its only lines are the doctest timing line.

**The whole test files stay where they are.** `cities_tests.rs` and `harness_tests.rs` are already sibling files, mounted
from `lib.rs` by `#[cfg(test)] #[path = …]`, and `shape.py` does not count them as tails. `cities_tests.rs` reaches
crate-private items: `building_is`, `squad_of` and `captain_of` are `pub(crate)`. `harness_tests.rs` is `lib.rs`'s own
`tests` module. Moving either to the crate's `tests/` would make it an integration target and rename all 312 of their
tests in the gate's timings file. That gives no count back, so they stay. `docs/STRUCTURE.md` §6 records the reason.

## What the move broke, and the fix in each reader

Three readers of the simulation's source keyed on the old shape:

- **`rondata::writers::blank_tests`** had the hole 4008 closed in the float scan. `#[cfg(test)]` blanked up to the end
  of the *next* braced block. After `mod tests;` that block is the next production item, which matters in the seven
  files whose declaration now has code after it. New: `mod_decl_end` ends the item at the `;` of a bodiless `mod NAME;`
  and touches nothing else.
- **`writers::three_views`** read the flat `src/` only, so the moved tests left its test view. It now also reads every
  `*tests.rs` one directory down (`sweep/` excepted, since it is read already). The no-reader ledger reads **8 rows**
  with the `mod_decl_end` fix and 8 with it disabled. The fix uncovers nothing new, and the test view holds what the
  tails held.
- **`nations::tests::sim_sources`** names each file by its file name, and `docs/NATIONS.md`'s "modelled at cost.rs" rows
  found their witness in `cost.rs`'s test tail. The test failed with 14 rows: `russian_spy_cost`, `roman_fort_cost` …
  `0064f3b0` at `airbase.rs`. A `foo/*tests.rs` file directly under `src/` is now named `foo.rs`, which is what the
  old one-file view saw. 11 passed.

The float scan and `docs_guard`'s test-file list read `no_float::module_tree`, and 4008 taught it `foo.rs` → `foo/`.
Both needed no change. **Failing once on purpose**: with `cliffs.rs`'s `#[cfg(test)] mod tests;` deleted,
`no_float::tests::every_source_file_is_mounted` failed (`sources no module tree mounts: ["cliffs/tests.rs"]`) and so
did `the_simulation_holds_no_floating_point` (`cliffs/tests.rs:7: f32` …). Restored, 41 pass.

**Line citations.** A script listed every `<file>.rs:N` citation, with or without `crates/sim/src/`, across
`docs/**/*.md`, `crates/**/*.rs` and `tools/**/*.py` (never `tools/emu`) for the 100 files, wherever `N` fell inside a
moved block or after one. **No live document or source comment cites one.** The 67 hits are all in dated records:
`docs/audit/2026-11-06-territory-*.md`, three journals and one `PARKED.md` row. They cite the tree as it stood on their
day and are left as written. `tools/paths.py --check` still lists only the 12 pinned citations; no file path moved, so
`paths.py move` had nothing to rewrite.
