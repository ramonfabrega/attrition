## The switch, and the runner's `--rise`

`Game::do_frame@00591ef0.c:300-304` saves and reloads the whole game when `auto_save_load` is non-zero and the
just-incremented frame divides by it. `Game::solo_checks@00588110` reads it off `rise.ini`'s `AutoSaveLoad`, and every
lane's ini holds `AutoSaveLoad=0`. The runner (`tools/explore/unattended_capture.py`) gained `--rise KEY=N`. The keys
it takes are those in `RISE_DEFAULTS`, each with its stated default, and today that is `AutoSaveLoad=0`. **Every take
writes every such key**: the flag's value, or the default when the flag is absent. So a later take on the lane never
inherits a 650, whatever the profile restore did (Loop 3488's rule). A key with no stated default is refused before a
byte is written. The receipt records the values written (`rise`). Tests: `test_a_rise_key_is_written_on_every_take_with_its_default`
and `test_a_take_removes_only_the_saves_it_added` in `tools/explore/test_unattended_capture.py`, which is in
`tools/offline_tests.py`. The offline suite runs 697 tests, OK. No other default changed.

**Where the save lands**: in the launch's working directory, which is the run's own `map-14/autosaveload.svx`
(about 318 KB). It does not go under the prefix's `Documents`, as D2's reading guessed. My first version of the cleanup
watched `~/Documents/My Games/Rise of Nations/Saves`, and run1115 showed that was the wrong place (`saves_removed: []`).
The runner now removes any `*.svx` a take adds to its output directory and names it, with its size and digest, in the
receipt. run1116 is the first take that cleanup removed. run1115's save was removed by hand (RUNS has both digests).
Because each lane has its own output directory, two pool takes saving at once cannot collide. I still ran the two
sequentially, before I knew that.
