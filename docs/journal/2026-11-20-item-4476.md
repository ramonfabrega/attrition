## The fix

`Unit::cavarch_uid` (`units/unit.rs`) is 0 at birth. `cavarch_take` writes it on a find, and so do
`action_spell`'s arm and `do_cast_targeted` (`spells/cast.rs`). Nothing clears it. The units line reads the carried
word (`checksum/units.rs`).

**Test.** `row_60_s_dragoon_keeps_its_dropped_target_s_uid_on_run1722_s_ranges` (`diff::held_out`) compares every
units range on 3756 and 3757 byte for byte. It also checks theirs' record 21 by name: `cavarch_o` 11, then −1, and
`cavarch_uid` 18 on both states. **Mutation**: `tools/mutate.py --edit crates/sim/src/combat/cavarch.rs` replaced
the find-only write with `let id = found.map_or(0, |t| self.obj_uid(t)); self.units[u].cavarch_uid = id;`, which
clears the uid on an empty search. It held: zsh exited 101, and the one failed test was that one, at `units range

first mutant had a borrow error. The second failed because my own test read a `field` that theirs' `Range` does not
have. I fixed the test (`57e859c97`) and ran it green before scoring the mutation.
