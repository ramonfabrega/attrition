## The mechanism

`myarmor` (`UnitData +0x9c`) is a cache. Counted by offset in every spelling over the export, one function
writes it: `Unit::update_armor@006054c0:33` (and `:38` down the `o_down` chain). That function climbs to the
captain, takes `ObjectData::armor@00647db0` (type armour + `ages × DUTCH_ATTACK_BONUS` on a Dutch merchant
kind), and writes the value to the captain and its chain. It has four callers: `Unit::init@00612100`,
`Unit::set_type@00612fa0`, `SpellType::cast_create_decoy@00674370` and `Leader::calc_unit_stats@006cf970`.
`calc_unit_stats` runs from `Leader::process` on `0x4000000`, which `gain_tech`'s tail raises (4457).
`Leaders::process_all` runs before the objects, so an age reached mid-frame reaches `myarmor` on the next
frame. This crate folded `Sim::object_armor`, the live value.

**The fix.** `Unit::myarmor`, written by `Sim::update_armor` (`combat/fight/stats.rs`) from `Sim::add_unit`,
from `calc_unit_stats` (every live figure: each climbs to the same captain), from the `set_type` adapter
and from the decoy cast's refresh. The units record reads the cache. Combat's `armor_of` still reads the live
value (parked 4464b).
