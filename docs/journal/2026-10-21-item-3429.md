# Item 3429 — `cover=1` runs on the click-free lane (2026-10-21, `att-3429`, Opus 5.5)

**The result: the fix.** The rest of the tranche's `cover=1` captures may take the click-free pool and run in
parallel; the queue lane is no longer the only lane for them.

## The hang was a refusal

The item booked run185 as a startup hang with the call proxies under suspicion, and named the attach order and the
stub forest. The disk answered first. run185's own trace was overwritten, but chapter thirty-five's two dead
`cover=1` takes are kept (`~/ron-golden/ch35.dead-20260928-0154`, `-0308`), the same lane and the same 96 KB. Read
with `report.read_log`, each holds 2,984 `HIT`, five `hooked`, eight `proxied`, `cover`, `armed`, `attach`, `cmds` —
and one `INFO 174` with code 1 and `g_cover` 1. That record is `install_autostart`'s refusal
(`tools/explore/live_autostart.h`): its validation began `if (g_cover || …)`. The lab note had written the exclusion as
a scope ("coverage instrumentation is excluded") and given no mechanism. With the driver declined, the game sat at
the main menu waiting for a click the click-free lane never makes. The runner's timeout (run185) or its stall guard
and relaunch (chapter thirty-five) ended it. The stubs, the proxies and the threads were not at fault: the last
record is a startup `HIT` because the menu loop calls nothing new.

## The fix

There was one real conflict under the refusal. Two of the driver's patch sites are function entries
(`TopMenu::main_menu@0059bf70`, `TopMenu::sub_menu@0059c030`) and one is `System::modal_idle@005994a0`, so `arm_all`
plants its own jmps exactly there. In the old order, autostart then cover, `arm_all`'s jmps would have overwritten the
driver's. The fifth site, `0x5c7e37`, lies inside `SetupWin::exec@005c67f0`, far from that entry's displaced range.

- `check_autostart` is the old byte validation, minus `g_cover`. It still runs right after `install_hooks`, on the
  shipped bytes, before any stub exists.
- `install_autostart` now runs after `arm_all` and before the flusher thread is created, so every code write is
  still on attach's one thread ("Coverage is back"'s first rule). Its jmps replace the stubs' at the three entries.
  The menu functions are replaced outright, as before. `modal_idle`'s original is now called through its coverage
  stub (`cover_entry`, the issuer guard's precedent), so the idle loop is still recorded. With `cover=0` it gets the
  six-byte trampoline as before. `INFO 175`'s second word says which.
- No new instruction class: the driver's wrappers already used `lahf`/`seto`, never `popad`/`popfd`.

Modules touched: `tools/trace/tracer.c` (DllMain's order), `tools/explore/live_autostart.h` (the split). Paperwork:
`tools/brief/frame.md` and `docs/audit/README.md` (the 1047 row retired, struck with its pointer),
`docs/ORACLE.md` ("Coverage is back", amended in place), `docs/lab/2026-09-09-autostart.md`, `docs/RUNS.md` (run185
read, run1037), `docs/PARKED.md` (slot MQ → 3429a, 3429b).

Checks before the capture: `tracer.c` compiles clean under `-Wall` in the plain, `RON_AUTOSTART`,
`+RON_REPLAY` and `+RON_STARTUP_PROBE` builds. `test_autostart_abi.py`, `test_autostart_receipt.py` and
`test_capture_lanes.py`: 26 passed.
