## What the reading found

- **The key.** `Options::exec`'s `OPTION_PAUSE` calls `TurnControl::issue_toggle_pause@00956b40`. In a playback it
  toggles locally. Otherwise it adds `pause(!bit)` to the local package.
- **The processing.** `TurnControl::process_pause@00956990` logs when `state` equals the bit. Otherwise it toggles,
  and in solo it resets the frame clock and puts up the notice.
- **A paused game turns but does not step.** `do_frame_solo` runs `process_turn` on every call, but
  `check_new_frame_solo` (and `_playback`) answers 0 while the bit is set. So every package issued while paused
  carries the frame the game stopped on.
- **The recordings agree** (`PAUSES_HELD`, new): 12 pairs, each `pause(1)` and `pause(0)` on one frame, with 70
  packages between them across the twelve. The next package is always on a later frame. Seen red pinned `(12, 0)`.
