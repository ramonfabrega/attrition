# Item 4013 — `sim::ids`

Opus 5.5, lane A, base `e22f51f14`. One session. A `structure` item (`docs/STRUCTURE.md` §4, §5 move 5) and the first
one that renames rather than moves. I ran no capture and took no packet, and nothing under `tools/emu` changed. **No
behaviour change:** every edit is one of four kinds. A definition moved to `sim::ids` and its old home re-exports it.
A name was renamed at its definition and at every use. A private alias was derived from the single definition. Or a
rondata survey check was added. No statement was reordered, so the rng stream is untouched.

**The owners of bare names**: `combat::mask` keeps the `obj_masks` letters (`AIR`, `FOOT`, `MOUNTED`, `NAVAL`, `SIEGE`,
`CIVILIAN`, …). `ids::ty` keeps the type names, `ids::cell` the `WData` words, and `ids::spell` and `ids::order` the
original's own words. A family that collides with one of those takes a prefix. The prefix covers the whole family where
most of its members collided (`LINE_`, `IS_`, `ROLE_`, `UNIT_CAT_`, `FORM_CAT_`). Elsewhere it covers only the colliding
members.

**The look-alikes stay apart and are renamed**, as §1 requires. `ai_load::cat` (`UNIT_CAT_FOOT` = 0) and `form::cat`
(`FORM_CAT_FOOT` = 3) stay separate. So do `ai_load::role` (`ROLE_*`, the original's word) and `combat::role` (`IS_*`,
the port's), and `cell::MOUNTAIN` 0x10 and `coord::MOUNTAIN_VERT` 0x2. `terrain_groups`' draw site `ORTHOG` became
`ORTHOG_DIR`, and no `ORTHOG` neighbour table was touched. The two `cat` modules share every name in `ai_load::cat`, so
the renamer told them apart by file. `ai_load::cat` is named only in `ai_load.rs`, its tests and `ai_units.rs`; every
other `cat::` is `form`'s. A wrong pick would have been a type error, since one is `i32` and the other `usize`. The
build was clean.

## `rondata` checks each family

Three new survey checks are in `crates/rondata/src/bin/rondata.rs`, one per family the install names. Each has its own
`NAMED_*` table in `sim::ids`:

- `every named nation id is its roster index`: 24 named, against `rules.xml` and `tribes/`.
- `every named spell id is its craftrules row`: 24 named, at `id − FIRST` in `craftrules.xml`. The pack and unpack rows
  are named `Pack`/`Deploy` four times each, so for those the check pins the pairing and cannot tell the engines apart.
- `every named type id is its rules row`: 30 named, at `id − 0x32` in `unitrules.xml` and `id − 0x19e` in
  `buildingrules.xml`.

**Each was made to fail once.** One release run had `("Maya", AZTECS)`, `("Sniper", SABOTAGE)` and `("Bark", TRIREME)`
planted in the tables. Its output, exit 1:

    [FAIL] every named nation id is its roster index — 24 named; Maya is 0
    [FAIL] every named spell id is its craftrules row — 55 crafts, 24 named; Sniper is 0x280
    [FAIL] every named type id is its rules row — 30 named; Bark is 0x154, which names Some("Trireme")
    3 structural check(s) failed.

With the tables restored, `cargo run --release -p rondata -- ~/code/fun/attrition/game` exits 0 and all three are `[ok]`.
The other families (order kinds, army status, the walks' enums, the cell and coord bits, the scales) are the engine's
own, and nothing in the install names them, so they get no check. **rondata's `Resource` is gone.** A cost letter `g`
still parses to variant 2, and `name_of` still prints "gold".
