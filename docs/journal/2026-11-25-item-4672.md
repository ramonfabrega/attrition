# Item 4672 — The siege muster's enemy-building search

Opus 5.5, lane `lane-4672`, base `99c66271e`.

The seam `muster::siege_find_building` is built. When a siege army's
muster finds no enemy unit beside a damaged, attacked building of the
target's city, it now asks for the nearest enemy combat building within
six cells. Before this item the crate answered −1 without looking.
**No score moved.** The search answers −1 at every entry on every
held-out walk, because no enemy combat building stands in range there.

## The reading

The source is `ObjectsData::find_building@0065d260`, called by
`Army::find_muster_spot@006f5cc0` with `(point, SEARCH_ENEMY, who, 0x1200, 0x200, FILTER_COMBAT, 0, 0)`.
`docs/ARMY.md` §27 has the full reading.

- **Radius.** `0x1200` selects the circle arm, so the walk covers
  `circle_radius[6]` cells around the point.
- **Region flag.** `0x200` restricts the walk to cells in the start
  cell's region.
- **The `FILTER_COMBAT` arm.** I read it off the listing at `0067de47`,
  because the decompiler cannot follow the jump table. On a building it
  refuses a city centre (`+8 & 0x20`). It also requires a finished
  building, a type whose attack is non-zero, and `hits_left` above zero.
  Vslot `+0x1c` decides whether the building branch is taken. It is
  folded to `0041e0e0`, and in the PE that is `mov eax, 1`.
- **Distance.** The distance is in tiles, and a tie goes to the last
  candidate in walk order.

The crate already had `find_dock_near`, a circle arm at `0x1800`. The new
`Sim::find_enemy_combat_building` follows its pattern.

**A difference from the crate's other building search.** The existing
`enemy_combat_building_near`, the 0x300 search in `do_forming`, tests
`attack != 0` alone. Read against the same arm, it lacks the city
refusal. Not changed here: no score names it (4672a).
