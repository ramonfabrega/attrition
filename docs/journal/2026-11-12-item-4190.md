## 1. The finding: draw 90 is the weathering

**The textures.** `Modern_Weathering.tga` and `age0_22.tga` are `Data/tilesets.xml` `<COMMON><WEATHERING>`:
- `WEATHERELEM name="Modern" age="2"` holds file1 and file2, both `.\terrain art\Modern_Weathering.tga`.
- `ALPHAELEM`s run TwoByTwo … SevenbySeven and NineByFive, every age's file `age0_22.tga`.

Neither file is in `Data/roads.xml`. Its age-2 page is `modern_road_pieces.tga` (`tilepage="0"`), and only ages 0–1
carry a TILEPAGE. `RoadsOut::render@008943d0` binds the page as stage 0. It binds a TILEPAGE as stage 1 only when
`i % 3 < 2`, i.e. ages 0–1.

**The card** (run1566b, the pass after 3279). This is the new test
`client::weathering::tests::draw_90_is_the_weathering_s`, which passes:
- **Draw 90** binds `[Modern_Weathering.tga, age0_22.tga]` with enables `0x1c204` and blend 5/6. Its options are
  `ENABLE_LIGHTING`, `NORMAL_MAP`, `SPEC_MAP`, `GLOSS_MAP`, `USE_UV0`, `USE_UV1` and `TEX1_USE_UV1`. Stage 0 is
  `MODULATE(TEXTURE, DIFFUSE)` with alpha `SELECTARG1(TEXTURE)`. Stage 1's colour op is 0 (DISABLE).
- **Draw 91** binds `modern_road_pieces.tga` with enables `0x20004`, which is `RoadsOut`'s plain state
  `field_0x188`, and `TEX1_NOT_BOUND`.

**Why 4182 read draw 90 as `RoadsOut`'s.** Draw 90's first return address, `0x89456c`, lies inside
`RoadsOut::render`. Draw 91's first frame is `Game::loop_render`'s `0x591a45`, with no `RoadsOut` frame at all.
`Scene::render@008b3270` calls `TerrainOut::render_weathering(0, 3)` immediately before `TerrainOut::render_roads`.
`render_roads` ends in a tail jump to the card's `+0x18`. So the card's draws flush one call late. **A card-trace
draw's `frames` name where it flushed, not who submitted it.** Read the state and the textures, never the frames
(for the Loop).

**The chain** (each function read in the decompile):
- `ObjectsOut::draw_weathering@00654a60` walks the render tree's objects. It skips one the console player has not
  seen, and it skips them all when `objects+0x224` mode `== 5`.
- `WallOut::draw_weathering@0063dde0` reads, per building:
  - It returns at once when `ObjectTypeData::domain` (+0x218) `== 1`.
  - Age is the owner's `LeaderDataEncrypt::ages` (+0xdc, `^ 0x62766`) when slot `+0x20` answers. For a `Build`
    that slot is `Buffer::is_pending_load`, folded, which returns 1.
  - **The size** is `x_size` and `y_size` (+0x234 and +0x238) when `is(VILLAGE 0x19e)` or `connects_to_roads`.
    Otherwise it is size+1, and only when `BuildData::city` (+0x72) `>= 0` and not (`is_gather_type` and not
    `is(UNIVERSITY 0x1a4)`). `is_gather_type` is the type's slot `0x90`, named by the PDB's `LF_ONEMETHOD`
    `vftable offset = 144`. Out of a city, such a type gets no weathering.
  - It then calls `Terrain::add_weathering(corner_x, corner_y, sx, sy, _, age)`.
  - A `FARM` (0x1a1) also gets `add_weather_underlay` 4×4. That is the underlay pass `render_weathering(4, 4)`,
    not draw 90.
- `WallData::tile_corner@00643440`: corner = the building's tile (`div3(pos >> 6)`, 192 units a tile) − `size >> 1`
  on each axis.
- `Terrain::add_weathering@00850120`:
  - The gate: `age > 5` **and** (`sx > 2` or `sy > 2`). The age bucket is 2 (Modern) for every age that passes.
  - The helper index is `2 · bucket + 1 = 5`, so the texture is `weather_textures_fertile_0[2]`, Modern's file2.
  - The alpha bucket is `TileSet::get_weathering_alpha_bucket(2, (sx−1)·(sy−1))`: the `ALPHAELEM` whose first
    byte is that product.
  - It lays the **(sx−1) × (sy−1) tiles from the corner**, `[cx, cx+sx−1) × [cy, cy+sy−1)`. Each tile is
    `TerrainOut::get_indexed_mesh@00863c50`'s quad: corners (x, y), (x+1, y), (x, y+1), (x+1, y+1) at
    `MinPolySize` spacing, z from `field_0x4a4` (the corner heights). The faces are (n, n+1, n+2) and
    (n+2, n+1, n+3).
  - The rotation r = `(int)(Fractal::get_height(texture_fractal, cx >> 2, cy >> 2) · 0x3d23d70a)`, capped at 3
    when it reaches 3.5. `TerrainOut::rotate_tex_coords@00863a50` turns it in quarter turns about (0.5, 0.5).
    **The float rounding at h = 25, 50, 75 is not yet settled**: emulate the `mulss` in f32 and check whether it
    is x87 or SSE on the listing.
- `TerrainOut::render_weathering@00852f70` binds stage 0 = the base, `weather_textures_*[bucket]`, and stage 1 =
  the alpha bucket's texture. The render state is `Terrain+0x42c4`.

**The UVs** (from the listing at `0x850700`–`0x8508c3`; `TexArray::add` takes u in xmm1 and v in xmm2).
dx = x − cx and dy = y − cy. Two sets:
- **Set A**, the first array (`-0x3c`, written to `-0xc8`). The four corners are (dx·q, dy·q), (dx·q+q, dy·q),
  (dx·q, dy·q+q) and (dx·q+q, dy·q+[ebp+0x1c]), with q = the float at `0xb69484`. **Read q** (0.25 expected) and
  the slot `[ebp+0x1c]` before trusting it.
- **Set B**, the second array (`-0x5c`, written to `-0xcc`). The patch-spanning UVs: u0 + dx·Δu_x + dy·Δu_y, with
  Δ = (rotated corner − rotated origin) / (sx−1) or / (sy−1).

Supposition, unconfirmed: A is UV0, the base (`Modern_Weathering`, repeating every 1/q tiles), and B is UV1, the
alpha, which is disabled in this draw anyway. `Modern_Weathering.tga`'s alpha is 255 everywhere, so **the patch is
an opaque rectangle of the base texel, crisp at its edge**, which is what the photograph shows. The shader is
`game/shaders/ps_global.hlsl` with `do_texture_operation` (`shader_texture_data.h`), lit, the stone-tile texel
under the ground's own light. The client draws the ground at the texel (§3.14), so the weathering can be the
patch pipeline's texel with a 1×1 white alpha.
