## 1. The finding: draw 90 is the weathering, not `RoadsOut`'s

The item booked the base as `RoadsOut::render`'s draw 90. Its textures say otherwise:
- `Modern_Weathering.tga` and `age0_22.tga` are `Data/tilesets.xml`'s `<COMMON><WEATHERING>`, and neither is in
  `Data/roads.xml`.
- Its state, enables `0x1c204` and lit, is not `RoadsOut`'s `0x20004`. That one is draw 91,
  `modern_road_pieces.tga`: the asphalt ring.

Draw 90's return address lies in `RoadsOut::render` because the card flushes one call late. `Scene::render` calls
`render_weathering(0, 3)` just before `render_roads`. The chain, the arithmetic and the evidence are in
`docs/RENDERER.md` §3.17; the card is pinned by `draw_90_is_the_weathering_s`.

## 2. What this session settled on the listing

- **q = 0.25.** The decompile names the constant at `0xb69484` `__real_3e800000`.
- **`[ebp + 0x1c]` is `1 / (sy − 1)`**, not q. At `0x850321` the routine stores set B's y step in the age
  argument's slot, which is spent by then. At `0x850853` set A's far corner adds it to `dy · q`. That corner is
  exact only at sy = 5. The capital is 7 × 7, so its far corner's v runs `1/6` past the near one where the step
  is `1/4`. It is kept as the listing has it and pinned by `set_a_s_far_corner`. A tile's mean cannot see it.
- **Set A is UV0.** `render_weathering`'s vertex-buffer call (`+0x40`) takes `Terrain +0x46e8`, set A, first,
  and `+0x46ec`, set B, second. The rotation and its float rounding touch only set B, which feeds the stage that
  draw 90 disables. The draft's open question on the `mulss` rounding is moot.
- **The predicate**, re-read in `WallOut::draw_weathering@0063dde0`. It is as the draft wrote it, with one
  sharpening. The non-connecting arm reaches `size + 1` only for a type in a city that is not a gatherer: a gatherer
  passes only as a University, which connects anyway. So the arm is the `NO_CITY` non-gatherers in a city.
  `tile_corner` uses the type's own size whichever arm passed.
