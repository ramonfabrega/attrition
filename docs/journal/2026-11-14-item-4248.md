## How it was built

- **The hook.** `check_all` runs on every pass of `Game::loop`, most of them on a state no frame moved (§24.1). So the
  hook copies a set's ranges into a buffer on every call and writes them only when the checksum hook calls the set
  due. A range belongs to the line whose value `check_all` logs next, the attribution `checksum.py` uses; the
  re-sums back it on every set.
  - The fold, `CheckSum::walk_function@00936ff0`, is `__thiscall (start, end)` with `ret 8`. Its six-byte prologue
    has no relative operand.
  - `check_groups` alone folds outside it: zlib's `adler32@005089d0` over eight words copied to a stack local, the
    call returning to 0x937587, read from the listing. Its ranges are kept from that return alone.
  - A rules line of 251,160 ranges a call is refused on the mask before any argument is read.
- **The costs.**
  - run1597 took 1,957 s against run1578's 1,792 s on the same line, 9 % slower.
  - About 238 KB a frame on average: 113 M ranges in 16-byte entries plus 3.9 GB of bytes.
  - The Rust tests read the record's 24,004 headers and every 97th set's body, in about a second.
- **Mutations** (`tools/mutate.py`), each `held — zsh exited 101`:
  - `+1` in Adler's high half turns `the_ranges_record_is_the_hook_s_take` red.
  - Dropping every one-byte range from the record's side turns `the_ranges_record_is_each_packet_s_stream` red.
  - The host test goes red with the mask cleared (`& 0u`): three cases fail.
