## The allocation's rule

`Stack<PathData>` is `list`, `size`, `length`, `increment` (`types.txt`, `0x10` bytes). Its methods, read whole:

- `init@0046d720`: frees, allocates 10, `size` 10, `length` 0, `increment` the argument. Its one call on a unit's
  path is `Unit::init@00612100:382`, with increment 10.
- `push@0046d820`: at `size <= length`, `increase_size(increment)`.
- `increase_size@0046e8c0`: `size += n`, reallocating. A negative `n` doubles. Unit paths never pass one.
- `pop@0046d870` and every clear only move `length`.
- `operator=@0046d7e0`: grows to the source's `size` when that is larger. Its one caller on a unit's path is
  `Unit::do_trade@005ed270:501`.

Three writers call `increase_size` directly, and each is an inlined push behind the same `size <= length` test:
`Unit::find_path@005fb910:161`, `Unit::do_group_move@005e79a0:247` and `Unit::do_air_physics@005e86d0:145`. So a
unit's `size` is its high-water path length since `Unit::init`, rounded up to a block of 10. The one exception is
a caravan after `do_trade`'s copy.

**Built**: `orders::PathStack` (`crates/sim/src/orders/order.rs`) replaces `Unit::path`'s `Vec`. It derefs to the
nodes as a slice, so readers are unchanged. Every call that changes the length is a method, and the ones that
lengthen it raise `size` a block at a time. `set` and `extend` keep the high water, as a clear followed by pushes
would. `take` empties the nodes and keeps `size`. The two `grouppath` swaps (`groups/grouppath.rs`) install a
scratch stack and give the unit's own back, so the scratch's growth never reaches the unit. That is the original's
static `grouppath`, which is not a unit's stack. The boat-to-rider hand-off in `ai/transport.rs` used `mem::take`,
which would have reset the boat's `size` to 10. It now uses `PathStack::take`. The emitter
(`checksum/units.rs`) walks `path.size()`.
