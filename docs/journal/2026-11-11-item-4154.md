## The rule

`Leader::calc_attrition` does not exit early when the step count is 0. The base is 0, and after each
applying arm `x == 0` becomes 1. So a Russian with a city and no `ATTRITION` step holds `att 1`.
A leader with no step and no arm holds 0. `attrition::strength`
(`crates/sim/src/territory/attrition.rs`) now does exactly that: `match tech_steps { 0 => 0, n =>
attrition_improved[n−1] }`, then `x = (100 + pct)·x / 100; if x == 0 { x = 1 }` per arm. That is
the original's `== 0 → 1`, not `.max(1)`.

The early return had no other dependants. `strength`'s callers are `Sim::calc_attrition` (the one
writer), `harness_tests.rs:54` and the module's own tests, and every one passes a default
`StrengthMods` at zero steps or a step count of 1 or more.
