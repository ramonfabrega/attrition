**Reading 4 stands, and it is the listing's.** `Unit::think_attack`
reaches `find_melee_target(−1, &who, 0, 1, 0)` and then
`Object::find_nearby_target`. There, `local_24` is set
(`64911b`–`64918d`) for STAND_GROUND, for entrenched without
`unit_masks2 & 0x20000`, and for a type that packs while it is
**unpacked**. The range gate (`6495c2`) sends a searcher with `local_24`
to `is_in_range` (`6486b0`). On a miss with `local_5c` clear, it skips
the candidate (`64963b`). `local_5c` is set only for a computer's packed
siege engine. This crate had the same three terms in its `anything`
flag, but read them as "takes anything". COMBAT §12.2 said the same, so
the prose and the code agreed on the inversion. The decompiler got this
one right: the listing is the decompile's shape.

`find_new_target` for any packer. It kills the attack and runs the idle
search again, and goes on only with what that search found. For an
unpacked catapult with its hitter inside the minimum, the search finds
nothing and the catapult stays put.
