## 1. The rule, from the code

- **Ensure** (`GraphicPieces::ensure_emitter@00904e60`). The live list is searched on `(who, o, system_type,
  node_num, gpiece)`. A new emitter takes `ParticleEmitter::init@008dcd00`: `start_time = frame · 67`, `end_time
  = frame · 67 + emit`, where `emit` is the system's `+0xac`, 67 for system 98. A live one found again has its
  `end_time` reset to the same value and its point and direction rewritten. `frame` is `gamec->frame`, the game's
  frame, whatever the render's cadence.
- **Stop** (`ParticleEmitter::inc_time@008dca70`). The emitter is stopped (`valid` 2) when `end_time < frame ·
  67`, so an emitter ensured on frame G runs through G + 1 and stops on G + 2: one missed frame does not stop it,
  two in a row do. It is cleared when `end_time` plus the system's `+0x78` is at or below `frame · 67`. Its live
  particles keep ageing until then, which is why `1/40`'s stopped emitter still shows 7.
- **The case-3 test** (`execute_graphic_events@00909a10`, lines 682–688): `last_time < endtime` and `starttime <=
  cur_time`, and `has_restrictions` passes. The Sherman has a single `<RESTRICTION>`, and the event's index masked
  to 2 bits is 1, so the test passes whatever `node_flags` holds. `GuyOut::draw@005dc490` sets `last_time =
  cur_time · 200 / 3` and `cur_time = last_time + graphic_dt`, clamped to `animmgr.times`; units with `+0x6c & 0x10`
  take `+ 66` for both instead. The Sherman's three events sit on `CHAR_SLOG`, `CHAR_WALK` and `CHAR_JOG` (slots 7, 8
  and 9), each `[75, 9000)`.
