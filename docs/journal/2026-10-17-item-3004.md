All ports are inlined in the sweep tests (no crate consumer), so the census scores them as `sweep`-backed.

**Starved draws read and fixed**: `get_queue` first faulted on a wild `get_first_library` answer (`--answers` lists
are 90 %, the rest wild: `--answer-range 2:-1:5` instead) and then on a `--tame`d line (`--tame` needs `--ecx-int`/`--edx`);
`find_special` first returned -1 on 345 of 400 rows and was biased (counts, flag words, bit 15 of `+0x82`, radius).

**Not covered, said plainly**: `get_queue` takes `param >= 0` only (a negative index reads before the array; the
original would too and the window has no room before it); `count_farms` always lays `Build::vftable` on its buildings,
so the `call [edx+0xb8]` arm is unreached; `mnt_loc_*`'s own arguments (the index) are not recorded in
`total_gather_size`; `Game::walk_data` and `AmmoData::walk_data` were read and not taken (a stack byte written
through the walker's argument slot; `timeGetTime`).

Taken off the list and not built: `Unit::update_armor` (the `slot +0xa8` climb needs a terminating chain
of windows, no shape draws one that ends), `TurnControl::end_cannon_time` (a dozen-argument `add_message` with stack
temporaries), `Borders::remove_border_region` (destructors).

for the Loop: `--regen` with a bad flag set prints the error on stderr and leaves the old files in place, so a
`grep -iE error` that filters stdout reads as a pass (twice here); the generator could exit non-zero visibly.
