# Item 364 — the golden record replayed in the harness, and chapter one pinned

Rules track, Opus 5, its own worktree. The brief: an interpreter for the
record's cheat set and the command dispatch of `docs/COMMANDS.md` §3 onto
the sim's entry points, and the first `Golden:` word. The specification is
`docs/INPUT.md` §11; the implementation is `crates/rondata/src/golden.rs`
and the pin is `crates/rondata/src/diff/golden.rs`.

**The number is 617**, on a basis the file states in its own header and I
state again below, because it is not the long captures' basis.

## The first measurement was an artefact, and finding that out was the item

I had a word within forty minutes — **7** — and it was worth nothing.

`borrow_from_siblings` lends a capture the map it could not print for
itself: the heights, the world cells, the herds. It also lends the **setup
checksum trace** when the capture has none, and then, gated on the last
word of that trace matching, a sibling's **per-frame** words, which
`Built::tick` *installs* — the frame's own state replaced by the
original's, so the next frame starts on the true stream.

The golden capture has no checksum trace of its own, so it borrowed run11's
whole. The gate below then compared the borrowed word with itself and let
run12 and run13's fourteen per-frame words through. The comparison at those
frames was the correction, not the simulation: `mark_sites` said twelve
draws where the sim had spent fifty-four.

What makes it unfixable by a gate is the thing I did not expect. **The
golden record's `GAMEINFO` is byte-identical to run11's** — map 14, seed
12345, size 2, every one of the 34 option fields — and its setup checksum
word is the same `0x3bd39ae9`. It has to be: the script's first line runs
at frame 0's `do_frame` entry, *after* `Game::init`, so everything the
setup trace records is common to both runs and everything after it is not.
No gate on the map, the lobby or the setup word can tell a staged run from
an unstaged one. Only the caller knows, and the caller refuses by hand:
keep the borrowed setup, refuse `frame_seeds` and `frame_guys`.
`the_golden_record_s_setup_is_run11_s` checks the borrowed word against the
run's own trace rather than assuming it.

The commander asked the obvious follow-up before I could finish, and it
was the right question: does this reach the *scored* captures? It does
reach five of them and it moves nothing.

- Five Great Lakes captures — run33, run53, run89, run97, run100 — share
  the donors' setup word `1003723497` and take fourteen `frame_seeds` and
  fourteen `frame_guys` at frames 0–3 and 94–103. East Indies' setup word
  is `793793043`, which never matches, so run39/run54/run98/run99 take
  none.
- run53's whole 24,000 frames, walked both ways: **word parts at 9362,
  sequence at 9182, identically**. The installs are no-ops — the
  simulation already produces the original's word at each of those
  fourteen frames — and every one is at frame ≤ 103, nine thousand frames
  below the word. run33's ticks and orders are likewise unmoved.
- And structurally: `Built::tick` pushes `frame_sites` *before* it
  installs, so an installed frame's draw comparison is still the sim's own
  work. The install can only re-anchor the next frame.

That measurement is now a test —
`refusing_the_borrowed_frame_stream_does_not_move_great_lakes_word` — with
an anti-vacuity half asserting the borrow actually fires (14 against 0), so
"they agree" cannot become true by the borrow quietly going away.

crate's spends fifty-four: eight `MathUtilFuncSet::rand_int` and thirty-six

hundred frames. The control makes it a measurement rather than an
observation, and it is the single most satisfying line of the session:
run104 is chapter one with `0 !ai off` deleted, and **its frame 1 is this
crate's own, draw for draw, all fifty-four**. Our AI-on model of this map's
frame 1 was already exactly right; the only thing missing was the off

`ai_off` is one flag with three readers (`docs/INPUT.md` §11.4). Two are in
the simulation: `Leader::production_ai`'s head, which bails to the

is not — and `Unit::think@005f6e40:205`, whose block for a human leader is
exactly one statement, the `unit_masks & 0x40000` return that takes the
tail away.

**610 — `ai off` alone.** The frame `add hoplite who=0 4,40` runs. The
original spends three `Guy::init_real+0x52` draws there and this crate
spent none.

**617 — `add` modelled.** Two frames past the second spawn, so the
chapter's whole staged half is in.

## Three things the channel turned out to be

**A bare coordinate is a tile, and the runbook has the wrong arm.**
`parse_coord` has three: `c` or a bare digit under `coord_mode == 3` is raw
internal, `t` or a bare digit under `coord_mode == 2` is `n × 0xc0 + 0x60`,
and anything else is `n × 0x300 + 0x180`. This install takes the tile arm,
measured rather than read: `4,40` put the squad's head at `(888, 7800)`,
which is `(4 × 192 + 96, 40 × 192 + 96)` plus `find_nearby_spot`'s offset,
where the world arm would have asked for a point eighteen tiles away. That
closes 363's "the coordinate argument did not calibrate the way the runbook
says" — the runbook records the world arm, the channel reads the tile one.

**A bare number is not always a player.** `parse_who` reaches its digit arm
only when the caller passed a default ≥ 0. `age`'s first token is
`parse_who(·, −1)`, so `age 3` is player 0's third age; the token *after*
the level is `parse_who(·, console->who)`, so `age 8 1` is player 1's
eighth. I had this wrong first and a unit test caught it, which is the
argument for writing the offline tests before the fixture-backed one.

**Chapter one's `604 war` does nothing.** Cases 0x2c–0x2e print the
diplomacy table when the line has no further token. The squads engage on
the frame they are born because a Quick Battle already starts at war
(`docs/ARMY.md` §16.3), not because of the line. 365 should know that
before it writes chapter two.

## One draw named that was never named, and one that still is not

Frame 616 parted on a *label* rather than a behaviour: the original's
`Unit::fight+0x9b0` against our unit-loop phase mark. The draw was there —
`docs/COMBAT.md` §8.2 step 0's one-in-five re-search, spent since item 288
and documented down to the address — and had simply never been given a
`SITE_` name, so a frame that took it read as a bare phase. Naming it
(`sim::fight::SITE_FIGHT_RESEARCH`, plus its row in `crate::trace::SITES`)
moved the sequence parting from 616 to 617, where the count already was.

What stands at 617 is one draw and it is named:
**`Guy::set_anim@005da300+0xf2f`**, the variant roll `set_anim` takes when
the animation is `0xc` and a variant is asked for — the attack animation,
on the frame the auto-engaged squads first swing. This crate does not spend
it. The value diff parts one frame later, at 618. That is the next rules
item, and it is an animation item rather than a combat one.

## What I built and what I deliberately did not

`crate::golden` is the interpreter: the script format, `parse_who`,
`parse_coord`, `parse_type` and the eleven verbs, with everything else
refused by name and counted the way `crate::input::Applied` counts a
command kind. Four offline tests cover the grammar; the fixture-backed one
walks chapter one.

`Script::stage` is the small thing that matters most and was invisible
until it was wrong. `Sim::tick` clears `phase_marks` at its head, so a draw
a cheat spends before the call moves the stream and leaves no mark, and
`mark_sites` then drops it. The three `Guy::init_real` draws of `add
hoplite` were exactly that. `sim::Sim::staged_marks` holds them across the
clear and `tick` puts them at the head of the frame's own — which is where
the original spends them, at `do_frame`'s entry before phase 1.

I did **not** close `Sim::init_unit`'s seating seam. The original seats a
squad's members with `find_nearby_spot` around the captain before
`init_unit` returns; this crate leaves them on the captain's point. The
search takes no draw, so the word does not know — but the positions do, and
the golden dump has the exact answer for chapter one (`(888, 7800)`,
`(1032, 7800)`, `(936, 7944)`). It is a change to a function every
production path calls and it belongs in an item that re-runs those pins.

I did not touch `borrow_from_siblings`. Making the refusal the only
possible behaviour is a guard and the commander ruled it the steering
pass's.
