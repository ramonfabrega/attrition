## `do_damage`, after the commander's question

The first landing introduced a regression: `FIGHTERBOMBER` fired 16
damaging rounds a swing where the original fires 10, because it read
both nodes and not `do_damage`. The commander asked whether reading the
flag was in reach. It was, and the whole path is in the export:
- `init_ammo_piece_ranges@008f6140` reads `do_damage` (default 1) and
  keeps a zero as `ammo_flags |= 0x80`;
- `Ammo::init:151` sets the round's `0x10` from that;
- `Ammo::inc_time:260` calls `do_damage(this)` only without `0x10`, and
  otherwise `close`.

Built:
- `artdata::harmless_ammo` reads the three names from
  `effects_graphics.xml`;
- `piece_releases` keeps **every** event as `(frame, node, harmless)`, so
  the collapsing of repeated pairs is gone;
- `Projectile::harmless`, set in `fire_ammo_aim`; a harmless round is
  closed without `land`;
- the harness compares `flags&16` in `ammo_flag_rows`, on all three
  `AMMO` walks;
- `group.rs`'s fixture takes the third field (`false`), under the same
  grant.
