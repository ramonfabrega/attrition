## 2026-09-17 — item 328: the ring walks, and the seam whose premise expired (Opus 5)

**The score.** Great Lakes' long word **8186 → 8187**; the sequence with
it, 8186 → 8187. One frame, and the frame it closed is the one item 324
specified and deliberately did not implement.

**What the brief overrode, and why it was right.** 324's argument was
honest: §17.2-§17.4 is single-reading arithmetic, and coding from an
unratified reading is how a wrong formula gets pinned. The commander
overrode it on `CLAUDE.md`'s own rule — the implementation *is* a pass of
the audit, because prose can cite every address correctly and still have
the arithmetic wrong, and no adjudicator can see that without doing the
work. Writing the code found **four** errors in §17 that the reading had
not, and a fifth in `docs/ARMY.md` §12 beside it. Each is struck in place
with its successor named:

1. **§17.3's far arm is unreachable for a building.** The outer switch is
   not the distance, it is `is_unit(target)`; and a unit target never
   reaches the ring at all, because the ring's gate is `is_build`. The
   two vtable slots are COMDAT-folded onto `return 1` / `return 0` and so
   cannot be read off `vtables.txt` — what identifies them is that
   `Unit +0x18` and `Build +0x1c` share one fold and the other pair share
   the other. The row read as "target further than `(range + 8) × 0xc0`"
   is real, and it feeds only the half of `00601280` that this crate does
   not model.
2. **The `max(0xc0, …)` row was missing a term** — `+ big_radius − 0x30`
   when `range < 10` — and its bracketed subtraction is a **unit**-target
   term. Great Lakes' archers have `range = 12`, so neither applies and
   `local_18 = 2208`; 2208 is what puts `1/27` on run19's own
   `(4344, 29736)`.
3. **`UnitTypeData +0x244` is `big_radius`**, not the block radius. §17.2
   and §17.3 both said block radius; the type record settles it.
4. **`find_building`'s `0x200` is the flag word, not a radius.** The
   radius is the `−1` before it. A negative radius takes the exhaustive
   arm — every object, no distance bound, tile-space distance, ties to
   the last — and `0x200` is `param_6 & 0x200`, the region filter. Read
   as a radius the probe finds **no farm at all**: the farm is 1,165
   position units away and `0x200` is 512. That one cost the longest, and
   it is exactly the kind of error that would have cost the next reader a
   session.

A fifth, new rather than wrong: **an asker whose activity order is index
12, `GUARD`, is not moved at all** (`601616`).

A seam is a claim with a premise, and a premise can expire without anyone
editing the seam. That is a fourth species of paperwork fault beside the
day's three, and it is worth looking for wherever a seam's reason is "no
capture reaches this yet": the sentence stays true-looking long after the
capture arrives.

**A shared-behaviour change, said plainly.** `do_attack`'s `HOLD_FIRE`
early return is now gated on `!mandatory`. The probe sets
`action_stance(5)` — HOLD_FIRE — on the six units it then gives a
mandatory attack order to, and with the old gate not one of them moved.
`Unit::do_attack@005f1b80:225`-`244` is the citation: the order's `+0x1c`
jumps straight to `LAB_005f2224`, the unconditional `fight`, and every
stance test in the function sits under `mandatory == 0`. **This changes
behaviour for every unit in every capture, not just the probe's six**,
and what would have caught a regression is the release gate's own diff
suite — every `run*` window test and both maps' words, which is what it
was run against; nothing outside 8186/8187 moved. If a later capture reds
on a mandatory attack in a non-aggressive stance, this is the change to
look at first.

**8187, and why it did not go with it.** The brief asked for both. 8187
spends one draw at `PathFinder::astar_path+0x1697`, and the read is
clean: it is the **failure tail** of a unit-grid search
(`astar_path@00683770:964`, `param_2 == 0x30`, the open list exhausted) —
`Random::get(0, 0xffff) % 3 + 6` written into the order's move data

original does not take. So the item is not "emit one more draw", it is
"make the unit-grid search refuse where the original's refuses" — a
pathfinder item, and `crates/sim/src/path.rs`'s exhaustion tail already
names it as a seam. It is written up in `docs/COMBAT.md` §17.6 with the
address and the gates, which is the whole of what a successor needs.
