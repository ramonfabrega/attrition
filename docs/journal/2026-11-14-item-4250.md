## What the reading found

- **All 160 chats on disk are cheat lines**: `bits` `1 << who`, `taunt` 0, `taunt_num` 0, text `cheat …`. The 2017
  sample carries none. Each one's package holds the chat alone, beside `camera` and, in 41 of them, `player_speed`.
- **The two arms of `ChatBox::on_modal_end@0093d560`.**
  - A line with the cheat prefix (`get_cheat_string`, the install's `CHEAT `) goes straight to
    `CommandManager::issue_chat(who, line, 0, 0, 1 << who)`. That is the recorded form.
  - Any other line goes through `LeaderOut::issue_chat@006d2c50`. On the plain box (`special_flags` 0) it names the
    slot and every live, unmuted leader (`chat_status` 0). `taunt` is `Taunts::check_for_order`'s −1 for a line that
    is not a taunt's number. Below three nations the text is unchanged.
- **A plain chat writes nothing the simulation keeps.** `CommandPackage::process_chat@009454f0` hands it to
  `Leader::receive_chat`, which only displays it, and calls `Leader::receive_taunt` only when `taunt` is not −1.
- **The effect can still be seen on the original's side**: the trace's first-hit coverage dates `process_chat`'s first
  entry. In a playback with no chat, run1598, it never runs.
