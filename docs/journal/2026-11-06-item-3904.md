## The falsifier, written first

Written before any reading for a producer. **No producer exists if every path that gives a unit a group move
under a new group (or a new id) first clears the old group's move from that unit's list** — that is, if the
regroup paths (`Group::clear`, `add_group_move_order`'s `QUEUE_NEW` clear, `finish_insert`'s re-issue, and any
`QUEUE_LAST`/`QUEUE_FIRST` add to a unit already holding a group move from another group) either empty the list
or cannot coexist with an id collision `(gidA + f·10)·100 + nA = (gidB + f'·10)·100 + nB`. A producer is a path
on which one unit's list holds two type-19 or type-21 orders with equal `+0x5c` ids **and** a non-move order
(the `ATTACK`) between them, at a frame where `find_new_target` runs for that unit.

- **The falsifier fails.** `Groups::push_group` moves a member out of its old slot through `Group::kill`, which

  `QUEUE_NEW` clears, in `action_move_near`'s member loop and in `add_group_move_order`. So a regroup onto a
  `QUEUE_LAST` move keeps the old slot's move queued.
- **The ids meet.** Player p's slots are `64p` to `64p+45`, filled first-open-first. An emptied slot's counter is
  zeroed by `Group::clear`, and so is a fresh slot's. So `(gA + 10fA)·100 + nA = (gB + 10fB)·100 + nB` when the
  slots are 10k apart, the frames k apart the other way, and both counters are 0. One slot cannot meet itself
  short of a thousand actions between clears.
- **The walk kills the first k orders for k matches**, so a duplicate anywhere at or below the `ATTACK` kills it.
  The list runs current first; the orientation was read off `LinkListBase::add` and `tail`.

  not. So the list `[GM_form X][ATTACK t][GROUP_PATROL][GM_B X]` comes from five commands on two frames, with
  slots 0 and 10 (§390.3).
