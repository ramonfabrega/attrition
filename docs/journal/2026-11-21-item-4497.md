## The reading

- **One `Ammo` per pool slot.** `Objects::add_ammo@00658b10` takes the first pool entry whose `flags & 3` is clear. It mallocs
  a new one only when there is none, and it never frees one.
- **What zeroes the field, and what doesn't.** `Ammo::Ammo@0067b730` zeroes the dword at `+0x4` once, so a fresh `Ammo`'s
  `accuracy` is 0. `Ammo::close@006791a0` clears only the byte (`movb $0x0, 0x4(%edi)` at `6791a6`).
- **The field's one writer.** `accuracy` (`+0x6`) is written only by `Ammo::init:372` (`movw %ax, 0x6(%edi)` at `67c642`).
- **The bomb arm skips that writer.** It starts at the `[ebp − 0x30]` test at `67c289`, falling through to `67c293`. All its
  exits land past `67c642`: `je 67cff1`, `jne 67cb1f` and `jmp 67cbaa`.
- **The crash arm skips it too.** `Ammo::init_crash@0067b800` writes no `+0x6`, and `Objects::kill_guy@00659410` fills it
  from the same pool.

So a bomb carries whatever accuracy its slot's last aimed round left. That was the crate's own SEAM, "the recycled slot keeps
its last round's". `Ammo::hit_target@00678f90` reads it (`100 < accuracy`), so the value can also decide a bomb's hit on a unit.
