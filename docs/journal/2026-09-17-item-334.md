### What this did not establish

The flag's own fate is read, not diffed. `Build::process` does not clear
`build_masks & 0x100` on the way out, so a site's flag should still be set
when it finishes and fire on its first slot after that — which is what the
implementation does and what the new test asserts, but no dump on disk
reaches `1/2015` on 8193 to refuse it. A `BUILDS` record over `[8180, 8215]`
would settle it directly; `docs/ROADS.md` §1.1 names the row.

Nor does anything here say what happens to the *other* `Build::process`
statements this crate may still be running for a site. The gate was already
present in `process_building` — `if !self.buildings[b].active { return; }` —
with the replan the one statement above it that belonged below. Whether
anything else is misfiled was not audited.
