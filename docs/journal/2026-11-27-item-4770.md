## The reading

`Unit::fight@005fd4d0:1051` (`docs/COMBAT.md` §60.3), for a packer whose attack is not mandatory, calls
`find_new_target(this, &who, 0)`. `Unit::find_new_target@005ff6a0` does three things:

- `repath`;
- `kill_current_order`, or `Group::kill_group_order` for an order whose vslot `+0x2c` answers. That slot is the
  `GroupAttackToOrder` table's, so an `ATTACK` takes the plain kill;
- `find_melee_target(-1, &who, 0, 1, 0)`, whose add is `find_nearby_target`'s.

After the kill, the head is the `GROUP_ATTACK_TO`. So the add (`Sim::nearby_add` → `attack_move_add` →
`nearby_add_order`, item 3634) goes `QUEUE_FIRST`. A siege unit never hands the target to the group. The group order
stays, `on_duty` holds, and the chase's `MOVE_TO` goes in front.

Ours' packer arm was an inlined copy from before item 3634. It killed the attack, searched, and added
`QUEUE_FIRST` for DEFENSIVE and `QUEUE_NEW` otherwise. `QUEUE_NEW` closed the group order. Then the STAND_GROUND gate
(`get_combat_stance() == 2 && !on_duty`) returned before the chase.
