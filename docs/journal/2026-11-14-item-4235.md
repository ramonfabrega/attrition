## 2. The format, from the loaders

`MOTMethod::load@009164e0` maps the file and walks it with `ChunkRead`, the `.BH3`'s container.
`load_mot@00914a70` descends into id 0. It hands id 11 to `load_anim_header@00914970` and id 12 to
`load_frames@009146e0`. They fill an `AnimMeshPacket`, whose fields the PDB names: `num_frames`, `verts_list`,
`texs_list`, `faces`.

- **id 11:** u32 `num_frames`, u32 `n`, `n` × u16 indices, `memcpy`'d whole.
- **id 12:** its id 2 is `u32 n, n × 12` (a `Vert3Array`: three floats, not the `.BH3`'s four); its id 4 is
  `u32 n, n × 8`.
- **`SurfWaveSection::init@0089e8f0`** keeps the section only when `num_frames` equals both arrays' counts. It
  copies each frame's vertices as two floats. In the listing (`llvm-objdump`, `0x89eb6d`), x and y are each multiplied
  by the `.rdata` float at `0x00b695c8`, read from the PE as `00004040`, which is 3.0. The stride is 12, so z is
  dropped. `SurfWaveSection::draw@0089e360` writes z 0, which matches the packet's surf (item 4225: every vertex at
  z 0).
