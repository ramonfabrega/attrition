The original placed the same three units on the same points, and the
parting was on block 10766, in three rows, each read from the decompile:

1. **The members' orders.** `Unit::come_out` recurses into each member,
   and every call runs the same tail. For a computer's unit that tail is
   `close_orders`, `clear_partial_path` and `update_action`, so a member's
   `orders_x/y` are its new place. The crate ran the tail for the captain
   only.
2. **The slot's point.** A stack group's `ox/oy` are `Group::clear`'s
   (0, 0), and `copy_group` carries them into the slot. The crate copied
   the record default (−1, −1).
3. **The slot's speed.** `push_group`'s `equals_group` normalizes the last
   pushed slot on every push, so `Unit::go_to`'s push on 10766 resets slot
   71's speed to its leader's, 28. The crate never normalized there; the
   seam table even said so.

Each change took its own rows off run630 (`w630b.log` to `w630d.log`). The
word did not move.
