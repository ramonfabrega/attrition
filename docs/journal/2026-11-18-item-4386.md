## The probe

`RON_CARD_STREAMS`, under `RON_CARD_PROBE`, adds the following at `D3D11GLSys::render`'s entry, on each draw of a
logged pass. The layouts are `d3dgl.pdb`'s type records (`llvm-pdbutil dump --types`): `D3D11VertStream` `mDataPointer`
+0x18, `mLocalBuffer` +0x1c, `mStructSize` +0x20, `mLength` +0x24; `D3D11GLIndexBuffer` `mCurrentLength` +0x24,
`mLocalData` +0x28, `mUseDword` +0x1c.
- **The bound buffer** (`mCurrentVStream`, else `mVB`): its bytes over vertices [arg0, arg0 + max(arg1, the highest
  index + 1)).
- **The indices.**
- **The card's arrays**, when no stream is bound: `mV3`, `mDiffuseColors`, `mTexCoords0`, `mTexCoords1`. This is the
  surf's path: `Surf::draw@0089d6f0` calls the card's `set_vertices`, `set_texcoords` and `set_colors`, then draws.

Every draw has a local buffer, the shared lit buffer included (`0x0314b1c0`, stride 32), so the shared buffer's own
bytes are the surf's vertices. The arrays read as garbage through `mV3`, and I did not chase why. The layouts, read off
the bytes:
- **Stride 56** (the land, the floor, the water): position, normal, a diffuse dword (memory order R, G, B, A), uv0,
  uv1, and three more floats.
- **Stride 32** (the surf): position, diffuse, uv0, uv1.
