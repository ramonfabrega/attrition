# Item 3812 — the heights on Great Sahara (2026-11-03, `att-3812`, Opus 5.5)

**Map generation's seventh step agrees on every vertex of all 47 Great Sahara
start dumps that print the grid: 2,729,807 vertices**
(`great_sahara_s_heights_are_the_start_dump_s_grid`). `floors::MAPGEN`
GreatSahara moves 7 → 8 of 8 phases. The commander writes the `Mapgen:`
line. The item took two sessions; the first drafted at 328 k with the
falsifier committed red (`fbaaf4b4d`).

## What the dump's grid is

The start `DUMP_ALL` prints `master_land_heights` whole: 241 × 241 singles
on Great Sahara, row-major, `%f`, on the `UnbuiltForts` block
(`gamelog::heights_in`). It is taken after `Terrain::init`, and after the
starting cities and the start roster have terraformed it. So the 47 files
make 25 distinct grids from only two generated ones, one for 2-nation
lobbies and one for 3-nation lobbies.

## What writes a height there, in order

1. `generate_land`: `(a · 7.5 + land_height) + b · 1.875` in singles, `a`
   and `b` the two `Fractal`s (smooth 5 on `World.seed`, smooth 3 on twice
   it, flags 2 so `get_height` answers `h·100 >> 8`). `land_height`
   (0xcbe54c) is 30.0f; the decompile prints it as a constant, and it is
   not one. The fractals' bilinear sample runs in a software double
   (`sim::double`). `find_closest_coordinfo` finds no 0x20 cell, so there
   is no blend and no `smooth_tcoord` list.
2. **`TerrainOil::create_doobers@008a28e0`**, which `Terrain::init` calls
   at `Terrain.cpp` 738, between `generate_land` and
   `adjust_for_mountains`. A cell with the rock bit (0x8) that is not ocean
   reaches `add_rocky_patch@008a2b30`. On an `OIL` cell (0x800) that runs
   `terraform_for_building(4c, 4c, 4, 4)`, with the building
   terraform's own mean, border and refusals.
3. `adjust_for_mountains` → `fill_mountain_data`: each mountain's
   `TEMPLATE_TEX` displacement, `byte · (height · 3) / 255`.

## How the last two partings were named

The draft's falsifier parted on 796–1,265 vertices a file. These are the
two causes, found in order.

**(231, 43) on the 2-nation files.** That vertex is cell (57, 10). The
start dump's object list puts an **Oil** `GOOD` (o 6, who 255) at
(44928, 8832): 768 world units a cell, so cell (58, 11), whose 4×4
terraform box is vertices [231, 238) × [43, 50). The grep for
`terraform_for_building`'s callers names `TerrainOil::add_rocky_patch`.
`Terrain::init`'s listing places it before the mountains, so it belongs to
map generation, not to the roster. Built as `map_heights::create_doobers`.
Parted vertices fell from about 800 to about 311 a file.

**(208, 84), ours 213.75 against the dump's 243.14.** The 314 vertices
still parted on run1000 formed two clusters, around cells (53, 22) and
(8, 39). Those are the two players' `o 2000`, the starting cities. The
dump's interior there is flat (272.531 and 663.703), and ours was not
flattened at all. The cause is in the harness, not in the sim:
`diff::setup::build_sim` stands the cities through `init_build`, which
terraforms, **before** `start_of_game`, where the test hook installed the
generated grid. So the cities flattened the dump's grid, and that grid was
then overwritten. The hook now installs the generated grid ahead of the
cities (`ON_GENERATED` carries the flag to `start_of_game`'s tail). With
that, all 47 files are green.
