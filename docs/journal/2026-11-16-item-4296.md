## The first act: the byte

`llvm-objdump` at `873d5e`: `movb 0x55dc(%esi), %al`, one byte, then `movzbl`, add, `cmpl $0xff`, `jae` to a store
of `0xff`. So each channel is `min(255, floor + b)`. The type record's `+0x55dc` is `ocean_t_scale` in
`TerrainData`. But the decompile's terrain pointer sits 0x40 before `TerrainData`'s record, which
`tools/render/water_packet.py` already says. So the byte is `TerrainData +0x559c`, `OceanVars +0x78`:
**`trans_bright`**, a `uchar`. `OceanVars::registration@0084f260` registers it from 0 to 255. On run1564's packet
(`~/ron-golden/run1564/map-14/frame-snapshot.bin`, terrain `0x00c0b0f0`) it is **99** (`0x63`). The same read
gives `floor*_top` (255, 255, 255) and `floor*_bot` (64, 64, 64), as item 4174 read them.

## The ±6: the floor vertex, not the camera

`CoordInfo::add_geometry@0084bef0` is `modify_ocean_floor`'s only caller. It runs once per visible cell with the
floor flag (`0x2000`) on every frame, so this is not a one-shot. Each floor vertex at a cell's corner writes
its grey plus 99 into the land corners of its quadrant. A scratch script matched every deep corner of
`run1564-land-light.txt` against the packet's drawn floor vertices (`run1564-water.txt`, item 4174):

Where a tie's two vertices differ, the higher won every time: 486 corners, offsets (+2, ·) or (·, +2). So the rule
is `4⌊(c + 2) / 4⌋` on each axis (`ground::deep_grey`).

## The draw

`ps_global.hlsl` (the install's) runs the vertex diffuse through `do_texture_operation` into the stage,
saturates it, then `pow(color, 1.45)` times `diffuse + ambient`. So the grey replaces `light_vert`'s colour in
the stage and keeps the corner's own N·L. `land_lit_deep` does that.

The patch's third attribute carries `16 + 4 · grey + (nl + 1)` at a deep corner. `vs_patch` takes it apart into the
N·L and a `(weight, weight · grey)` varying, so a triangle with deep and lit corners interpolates the two colours.
`World`'s ramp re-lay writes it on every lit land layer: the faded base and the transition patches, never the coral
or a mountain. `TerrainOut::render` lays `add_patch` after the frame's `add_geometry`, and the patches copy
`+0x410` through `get_indexed_mesh`. It is drawn only with `land_light` on, so the off side of
`LAND_LIGHT_ROWS` holds.
