## The named candidate was wrong, and the falsifier said so in five minutes

Parked 460 was handed over with its falsifier already written, so it was
run first and exactly as written: `Profile::x_size` and `y_size` set to
`circle_radius` for every unit type,
`chapter_two_s_word_frame_is_widened_whole` re-run over `[620, 628)`.
**Not one row moved** — the divergence list came back byte-identical.

The prediction was written before the run, and it was that nothing would
move, because the row's premise is true of the *original* and false of
*this crate*. `attack_pos.rs:293` is inside `ring_walk`, which this crate
reaches only past `let Obj::Building(_) = target else { … }`, and
`combat::extent` takes its `x_size` arm only when `building` is true. No
unit-target path here reads `Profile::x_size` at all, so the field could
not be the residue however wrong its value.

That is worth writing down as a shape rather than as one row: **a
candidate derived from the original's control flow has to be checked
against this crate's**, because the two diverge precisely where a mechanic
is unmodelled — and an unmodelled mechanic is what a residue *is*. The row
named the right function and the wrong side of it.

## The harness could not see the real first divergence

Re-measuring before diagnosing is what found it. The widening's own map
said the first parting was at 622 on a destination. The dump's
`ATTACKORDER` on all three slingers reads `ox 8 whom 1 uid 14` — target
`1/8` — and this crate was chasing `1/6`, at 621, one frame earlier. No
row said so.

`OrderMismatch::Target` was live and `Built::target_ids` was answering
`None`. `unit_ids` resolves a simulation handle through `Built::units`,
which is the link table the **start** dump built;
`crate::diff::harness::compare` knows a unit trained or staged later is
not in it and links such a unit ad hoc by `(owner, index)` before
comparing it — but nothing did the same for a unit named as a *target*.
So the target field went silently uncompared for every target that was not
on the board at `BEGIN GAME`, which in chapter two is the entire cast. The
fix is four lines: fall back to the simulation's own `(owner, index)`,
which is the identity `compare` already uses.

This is `CLAUDE.md`'s "when the original dumps a record, diff the whole
record" one level in: the row *existed* and the comparison *ran*, and it
answered `None` on every frame of every chapter. A comparison that cannot
name one side is indistinguishable from agreement, and nothing was
counting how often it declined to.

## §12.2 already said what the code should do

With the target row live the cause was a twenty-minute read and no
capture. §12.2 has said since it was written that the scan takes, on each
cell, "every object on it (the cell's `down/down_who` chain, all
players)", and §18.1 *measured* that order against run108's bracket. The
implementation walked `(0..units.len()).chain(buildings)`.

The two orders agree whenever nothing ties, which is why this survived six
items on this chapter. Chapter two's three hoplites are the case that does
not: from `0/9`, `1/6` and `1/8` are 1459 and 1468 apart on a score that
divides by 192, so they land in the same bucket and `compare_target`
returns the same value for two undamaged figures of one type. The keep
test is strictly greater on both sides (`00649a6e`), so the tie goes to
whichever is reached first — the index reaches `1/6`, the chain reaches
`1/8`, and `Object::add_to_world` pushes on the head.

Grepping this crate before reading the original's writers is what made
that cheap: `collide.rs` has threaded `Unit::up`/`down` and
`Sim::chain_heads` since §3 was written. The chain was *there*; only the
search was not asking it.

## The unit half, checked against the dump before it was written

`00601280` splits on the target's `is_build` at `601604`; §17 is the
building side and the other side was not modelled. Three steps — the band
`[spot − 0xc0, spot]` by `0x60` where `spot = both big radii + stand`, the
bearing `find_angle(from − target)`, and an acceptance that is
unconditional for the far arm and otherwise "would I be in range standing
there".

The arithmetic was run on paper against run112 first, which is what made
this a measurement and not a try:

```
stand = max(0xc0, 6·0xc0 − 0x60 + (48 − 0x30) − 48) = 1008
spot  = 48 + 48 + 1008 = 1104,  band 912 / 1008 / 1104
```

and on ring **912**, at bearings `0`, `+1` and `−1` sixteenths, the
snapped points are `(1608, 8184)`, `(1560, 7848)` and `(1704, 8424)` — the
dump's three destinations, to the unit, before a line of Rust existed.
The implementation then produced exactly those, with the positions to
match, and `[620, 628)` closed whole.
