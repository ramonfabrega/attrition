## Why `process_console_cmd` did not enter

The `netcmd` on 640 entered `CommandManager::issue_console_cmd@00940fd0`. That function builds an `'N'` command
and calls `CommandPackage::add_command(&local_package, cmd, 0x209)` (`push 0x209` at `00941048`). `add_command`
returns 0 when `size + len > 0x200` (`cmp $0x200` at `0094baf8`), and a 0x209-byte command exceeds that with the
package empty. So nothing is packaged, and `CommandPackage::process` case `'N'` never sees it. run1088's dump at
`COMMANDMANAGER=2` has no `process_command_cmd` line. `issue_console_cmd` is the only writer of an `'N'` command,
so this is a `RESIDUE` proposal for the pass (parked 3471a). The predicate it failed is `add_command`'s size test
on 640, which no dumped field prints. The evidence is the issuer's entry with no `process_console_cmd` after it.
