# Jev: first contact and a useful retrieval result

## Result

On this branch's small exploratory set, Jev is promising for finding relevant
evidence in prose. Its behavior changes sharply with representation, and several
wrong arithmetic/formula answers have high reported confidence. No production
integration, simulation change, capture, or score move is claimed.

Model: `jev-1.13.0`. 263 retained HTTP requests, 314 question answers,
316,777 reported input tokens, approximately **$0.013305** at the documented
$0.042/million input tokens. An additional one-question connectivity probe used
300 input tokens and returned 0.03 for whether skipped fixtures establish fidelity;
that probe's response is in the task transcript, not the archive.

The eight-run [observation archive](2026-09-19-jev-observations.json) retains
requests, expected labels, distributions, model IDs, token usage and elapsed
times. Repeated state objects are interned by SHA-256; replacing `state_ref` with
its entry in `states` reconstructs a request. No credential is stored. The input
is authored synthetic cases and, with the user's explicit authorization,
excerpts from eight authored lab reports. No installed-game files or raw dumps
are included.

## Screen, then adaptive follow-up

| Task | First result | Follow-up |
| --- | ---: | --- |
| Evidence assessment | 11/11 scored | 11/11 with explicit wording |
| Bit membership versus equality | 14/16 | Not expanded |
| Integer multiply/divide/truncate | 6/12 | 12/12 given quotient and remainder |
| Hypotheses fitting observations | 12/12 on one relabeled template | 29/32 on varied answer sets; reordered repeat 30/32 |
| Experiment discriminating two Boolean rules | 0/12 with distractor | 2/12 without distractor; 12/12 in prose; 12/12 with computed predictions |
| Cheapest surviving one-tick action | 10/12 | Not expanded |

The initial hypothesis template always had the same semantic answer, so its
12/12 is weak evidence. The 32-case expansion varies observed inputs, true rule,
candidate subsets and expected answer. Follow-ups were designed after seeing
the screen, not held out. Cases within a family are correlated template variants.

Evidence case 00 is **excluded** from both scores. The initial wording left the
claim implicit; the follow-up changed it into a claim about what the results
establish. Calling that metaclaim contradicted is defensible, but the harness's
expected label remained unsupported. The raw automated summaries preserve this
labeling defect; the analysis excludes it explicitly instead of counting it as
a model failure. The other 11 labels remain the authored, provisional rubric.

The most striking failures: 66 × 3 / 200, truncated, was classified as 1 with
probability 0.93 (correct: 0); 333 × 3 / 200 as 5 with probability 0.94 (correct:
4). These observations do not estimate general calibration, but do refute any
assumption that high confidence makes this arithmetic reliable.

For experiment selection, H1 predicts `a`, H2 predicts `a AND b`; the separating
input is `(1,0)`. Removing an irrelevant target field helped only slightly.
Rewriting both rules and options into present/absent English raised accuracy to
12/12 and retained 12/12 with reordered options. Both formula runs scored 2/12,
with three individual choices changing. This is an association with the entire
representation rewrite, not an isolated effect of any single token. The repeat
also makes option-order and ordinary request variability inseparable.

Computed intermediates rescue the toy tasks, but computing their final answers
is already trivial in code. That is a boundary demonstration, not a reason to
put Jev after a calculator.

## Retrieval and batching

The retrieval set has eight reports, two manually authored paraphrased queries
per report, and two no-match questions. Each candidate is its filename and the
first 2,600 characters. Both no-match topics are absent: a Jev/Kev gameplay
comparison and a 144-fps renderer measurement. This is curated small-corpus
selection, not measured full-repository search.

| Method | Answerable queries | No-match queries | Measured time |
| --- | ---: | ---: | --- |
| BM25, k1=1.5, b=0.75, simple tokenization | 12/16 | No rejection threshold | Not benchmarked |
| Jev, independent calls, four workers | 16/16 | 2/2 | Median request 0.778 s |
| Jev, independent sequential calls | 16/16 | 2/2 | Whole workload 13.860 s |
| Jev, all 18 questions in one request | 16/16 | 2/2 | 0.858 s |
| Identical batch repeated | 16/16 | 2/2 | 0.805 s |
| Batch with reordered options | 15/16 | 2/2 | 0.882 s |

The first batch uses 10,600 input tokens versus 94,585 across the independent
calls: **8.92× fewer tokens**. Its latency is **16.15× shorter than the measured
sequential workload**. This is one local comparison, not a claim against an
optimized concurrent client: urllib opens requests independently, timing includes
network/TLS, and the serial run initially overlapped the short batch request.
No broader problem-solving speedup has been established.

The reordered batch confuses the activity-digest report with the RNG-determinism
report: whether a changing seed can fool a measure of activity. It gives the
wrong report probability 0.55 and the intended report 0.45. Both are useful
candidates for a reader, which suggests retaining ranked alternatives rather
than dropping everything except the winner. The identical batch's repeat was
correct. These few runs do not isolate the cause of the flip.

BM25 uses exactly the same excerpts and filenames. It has no fitted rejection
threshold, so its two no-match questions are excluded rather than counted as
failures. Queries and relevance labels were authored by the same investigator
who knew the documents; there is no independent query set or tuned search
baseline. The result supports further investigation, not deployment.

## Next experiment

The promising direction is a cheap batch reader over retrieved candidate
evidence: several specific research questions, one shared candidate corpus,
ranked source IDs returned for the reasoning agent to inspect. Test it on fresh
questions before building an integration. Include closely related reports,
absent answers, stale/overturned findings and requests requiring multiple sources.
Compare against tuned lexical retrieval and a reasoning-model baseline; measure
missed decisive evidence, not merely whether a plausible document was selected.

The evidence does not support putting Jev in charge of numerical verification,
acceptance gates, or formula-based experiment planning. No Kev installation or
training was needed to reach this first boundary. Whether Kev can specialize on
the useful retrieval task remains open.

## Reproduce

Offline, no credential or network:

```sh
python3 tools/explore/jev_lab_analyze.py
python3 tools/explore/jev_lab.py --dry-run --output /tmp/new-jev-cases.json
```

Live calls read `TYPESAFE_API_KEY` or retrieve the user-authorized Passage entry
in process memory. Output paths must be new. No environment file is created.

```sh
python3 tools/explore/jev_lab.py --output /tmp/new-jev-screen.json
python3 tools/explore/jev_lab.py --followup --output /tmp/new-jev-followup.json
python3 tools/explore/jev_lab.py --retrieval --batch --output /tmp/new-jev-batch.json
```

The opt-in scripts are not registered in the release gate and do not alter the
main loop. The offline analyzer checks interned-state hashes and recomputes the
reported scores, BM25 baseline, costs and batch timing from raw observations.
It does not independently certify every authored expected label. Live failures
are retained separately from semantic failures; a failed batch aborts.

Sources read: [TypeSafe skill](https://github.com/typesafe-ai/skills/blob/main/skills/typesafe-ai/SKILL.md),
[API](https://docs.typesafe.ai/api), [models/pricing](https://docs.typesafe.ai/models),
[Choice](https://docs.typesafe.ai/primitives/choice). Live docs checked 2026-09-19.

Validation: offline analysis, suite ID/answer-membership checks, and an independent
Boolean evaluation of all 12 experiment labels passed. The full explicit-install
release gate passed: 332 rondata tests (two ignored), 855 sim tests, 13 fixed tests
and three doctests, plus offline Python tests, install survey, clippy, formatting
and paperwork guards. The fixture audit recorded 782 requests with zero missing;
sampled process-tree peak was 12,189 MiB under the 20 GiB cap. Gate command:
`python3 tools/release_gate.py /Users/rf-studio/code/fun/attrition/game --test-threads 4 --report-dir /tmp/jev-lab-release-gate`;
full output is `/tmp/jev-lab-release-gate.log`. This validates repository
compatibility; the opt-in Jev probes themselves are validated by their retained
live responses and offline analysis, not by the Rust gate.
