# Loop 3392 and 3394: who signalled the lanes' children (pass 47)

Opus 5.5, from the transcripts. Times UTC; local is UTC−5.

**One sender for both.** A background subagent of lane att-3386
(`agent-a0610a818ea77c333`, "Sweep Unit::find_path", Sonnet) ran this from
**00:18:26.4 to 00:23:03.0** (19:18–19:23 local):

    until grep -q "^batch: [0-9]* break" res_04.txt; do sleep 10;
      pkill -f "debug/deps/sweep_u_z-a1902dc024a6fb79 unit_find_path" -n 2>/dev/null; sleep 1; done

macOS `pkill` stops reading options at its first operand. The trailing `-n`
(meant as "newest") becomes a **second pattern**, and `-f` matches it
against every process's whole argv. So every 11 s for 4.6 minutes, SIGTERM
went to every process on the host whose arguments hold `-n`: each `rustc`
(`--crate-name`), each `nice -n 10` child of `resource_budget.py`, each
`--nocapture` test, and each Claude Code Bash shell whose command text has
`-n` anywhere (`grep -n`, `head -n`). The loop survived because `pkill`
spares itself and its ancestors. Read-only here, `pgrep -f "zzzz_none" -n`
matched 7 (Bash shells, a `resource_budget` Python, a `cargo test …
--nocapture`, two `rustc --crate-name`); with `-n` first it matched 0.

**Exit 144 is how this harness reports a Bash shell killed by SIGTERM.**
`echo before; kill -TERM $$; echo after` → `Exit code 144`, with only
`before` printed. The supervisor did not send it: cancelled while waiting
for admission, it returns **130** (`tools/resource_budget.py:244-248`), and
the only signal it ever sends is SIGKILL, to its own child's group (`:198-211`).
