# Audit: the recorded-game container, blind second reading

**Date:** 2026-08-24. **Mechanic:** the `.rcx` container (`docs/RECGAME.md`,
`crates/rondata/src/recgame.rs`). **Method:** the standing pattern — the first
reader wrote the document and reader from the Ghidra export and the
heavengames sample; a blind second reader (Opus) re-derived the format from
the same export and sample without seeing the document, the implementation,
or `docs/ORACLE.md`; this pass adjudicated every disagreement back to the
decompile. The blind report is not kept in-repo (it lived in the job's tmp);
its content is fully absorbed below and into RECGAME.md's amendments.

## Where the readings agreed, independently

- The three wire primitives, byte for byte, including the String encoding
  and the one-byte markers.
- The **943-byte header map is identical in both readings**, field for
  field, down to the observed values (seed `0x144bd480`, `Seifer008`,
  `frame_to_break = -1` pinning the Game-range alignment).
- The section order, the 5·active+4 random blob and its read-and-discard
  loader, the rules layout (Constants 0xd40+4 with its duplicated 4-byte
  range, Balance 493×493 u16, 24 × 0x599 tribes), and the 18-byte package
  record ending at exact EOF.
- The package-stream start: the first reading's landmark (earliest nonzero
  24-stride marker whose package parse reaches EOF) and the second
  reading's backward dynamic program over all 1.68 MB **arrive at the same
  unique byte**, 1,025,193 — the strongest kind of agreement, two different
  algorithms with no shared code.

## Verdicts on the disagreements

1. **The container's compression — second reading right, document
   corrected.** The first reading said the recording path writes gzip.
   Verified in the listing-level evidence: `File::open`'s mode is a bitmask
   (bit 0 → zlib), `write_header` opens mode 2 (stdio, raw),
   `RecordGame::finalize` opens `recordgame.tmp` in mode 3 (zlib write) and
   streams the raw file through `Filemap` + `File::write`→`gzwrite`, then
   remove+rename. A finished file is gzip; an unfinalized one is raw.
   RECGAME.md §1 amended; the reader now sniffs `1f 8b` and falls back to
   parsing raw.
2. **The marker hash field — settled as `hash_value_insensitive`.** The
   first reading left it garbled; the second observed both use sites name
   the insensitive field. Accepted; §2 amended, §5 struck.
3. **AI difficulty — no conflict, two fields.** The second reading's
   "difficulty 5" is the lobby option (`GameInfo_u_24_s_0.difficulty`,
   Toughest); the per-player `diff` byte is 2 in both readings. The lobby
   union's 30 fields are now named in §3.1 from `GameInfo_u_24_s_0`
   (types.txt), which the first reading had left opaque.
4. **The GameInfo tail's strings — second reading's naming adopted**
   (workshop id, script, path, resolved dir, dropdown id, dropdown dir).
5. **The random blob's per-player 4 bytes are the leader's rolled nation**
   — the second reading matched them to the slots' tribes in the sample;
   consistent with the first reading's `leaders[who·0x6eec]+0x39c`. §4.1
   amended.
6. **The Types stretch — second reading went further.** Per-class grammar
   derived (90-byte common head + name String + class tails for
   Spell/Tech/Object/Unit/Build/Good), a walk of exactly 806 records spans
   the sample's stretch — and the class sequence is *provably* not in the
   file (positional dispatch; the byte-level parse is ambiguous). §4.2
   amended from "not derived" to "readable only against the type-table
   loader"; the landmark stays.
7. **Marker mismatch severity — warning, not stop** (severity-3
   `Error::report`, then keeps reading). §2 amended.
8. **Sections the first reading under-specified:** the CtW header's place
   in the sequence, and the embedded save being a raw byte-copy with **no
   length prefix** (so scenario recordings need the save format to skip).
   §4 amended.
9. **New observations absorbed:** wire order ≠ struct order in the package
   record (`stamp` fourth); the first field is `Game.frame`, not a struct
   field; stamps contiguous 1..N; `valid` = 1 only on the first record;
   `GameInfo.version = 0x06740124` does not decode as a `Version`
   byte-struct (open, §5); the version banner is written and never parsed,
   so playback checks no version at all.

## What changed in code

`recgame::read` sniffs the gzip magic and parses raw files too (verdict 1);
`Slot::diff`'s comment no longer implies it is the Toughest knob (verdict
3); the sample test additionally pins contiguous stamps and the `valid`
pattern (verdict 9).

## Confidence after the audit

High end to end for everything the reader parses; the two open edges are
the Types class sequence (needs the loader) and the command payload
encoding (the next mechanic). Both readings, two algorithms, and the
embedded combat table's cell-for-cell equality with the composed one all
pin the same byte boundaries.
