## Summary

**Counts, 46 rows:** twin 6 · twin-differs 4 · absorbed 16 · unmodelled 3 · replaced 4 · dead 7 · ui 3 · sound 1 · editor 2.

By stem: `spelltype` 11 (twin-differs 4, dead 3, unmodelled 2, ui 1, replaced 1); `subobject` 11 (absorbed 5, replaced 2,
dead 2, sound 1, ui 1); `unittype` 24 (absorbed 11, twin 6, dead 2, editor 2, unmodelled 1, replaced 1, ui 1).

**Twins the rubric does not count.** Six functions have a crate function that does their job, and I compared the predicate
or the arithmetic: `fill_relative_values` against `relative_value.rs:57`, all fifteen arms; `get_stance_type` against
`group.rs:2011`; `get_military_level_slow` against `tech.rs:1046`; `num_preq` against `tech.rs:966`; `is_siege` against
`group.rs:2263`; `research_time` against `production.rs:346`. The rubric counts them `layout`/`open` for one reason: the
Rust fn's name is not the method's snake case, or its doc comment does not spell `Class::method`. Sixteen more are flag
reads or thunks the crate inlines at their readers.

**Census findings.**

1. **Precedence.** `territory_kind` (`tools/census.py:1227`) returns `layout` for any backed function before it tests
   `is_dead_weight`/`is_ui_body`/`is_cut`. So `SubObjectData::play_sound` (which matches `play_\w*sound`) and
   `SubObjectOut::is_on_screen` (an `*Out` class) count as open although the existing marks catch them. Proposed: test
   the excluded marks before `backed`.
2. **Proposed class: empty body.** An export file whose body is `return;` alone. Catches `SpellType::cast_jam_radar`,
   `SpellType::cast_rally`, and item 1889's eight other empty voids.
3. **Proposed class: no caller, no slot.** Neither the export nor `vtables.txt` names the function, and the PDB lists it
   as non-virtual. Catches `SubObject::refresh_z`, `UnitType::gather_radius` and `UnitTypeData::get_circle_radius`.
   Reading `vtables.txt` would catch `SubObjectData::is_seen` too, since it sits only in abstract-base tables.
4. **Proposed class: the type editor's undo.** `^\w*Type::(backup|restore)$` catches `UnitType::backup`,
   `UnitType::restore`, and the `ObjectType` pair they chain to.
5. **Proposed UI pattern.** `underlay` (`UnitTypeData::get_underlay_circle_radius`), and a function whose only callers
   are `Options::picked_spot`/`Console::find_target` (`SpellTypeData::find_target`).
6. `SpellType::cast_pilfer` is dead by a property of the data, not of its name, and already sits in `blind::RESIDUE`.
   The census could read `RESIDUE` as an excluded mark.

**Proposed replaced group: the data walk (checksum, recorded game, save).** Pattern `::(walk_(rules_)?data|must_walk)$`.
In this group it catches `SpellType::walk_rules_data`, `UnitType::walk_rules_data`, `SubObject::walk_data` and
`SubObject::must_walk`. Every caller is `CheckSums::*`, `CommandManager::issue_check_sums`, `GameLog::say_checksum`,
`RecordGame::read_rules`/`write_rules` or `Game::restore_rules_data`/`dump_rules_data`, and the crate replaces each of
those (determinism by construction, `rondata` for the rules). The sibling `*::walk_rules_data` (`Type`, `ObjectType`,
`BuildType`, `TechType`, `GoodType`, `Tribe`, `Balance`, `Types`, `Game`) and `Object`/`Good`/`Item::walk_data` would
fall under it as well; check the `orders` stem's existing mark for overlap.

**Unmodelled, ranked.**

1. `UnitTypeData::get_kill_value@0061d3d0`, **entered** (run1018 …). The unit's kill value is the type's base plus, for
