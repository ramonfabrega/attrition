# Audit: the tech tree — second reading, 2026-08-20

Method: the first reading is `docs/TECH.md` and `crates/sim/src/tech.rs`. Two
blind readers (lean subagents on Fable 5) re-derived the mechanic from the
same export without seeing either — one over the predicates (`has_tech`,
`get_preq`, `special_preq`, `has_preq`, `techs_per_age`, `type_eligible`,
`type_avail`, `queue_here`, the loaders), one over the state (`gain_tech`,
`lose_tech`, `set_age`/`set_epoch`, `Leader::init`, `Build::finished`) — and
wrote reports to a scratch directory. Every disagreement below was re-read in
`~/ghidra-projects/decomp/funcs/<Class>/<method>@<addr>.c` by the adjudicator
and, where a virtual call's argument was dropped, in the bytes of
`riseofnations.exe` with `llvm-objdump`. Verdicts: **A** the document, **B**
the second reading, **both**, **ambiguous**. "Must change" at the end is what
was landed.

## 2. Disagreements, adjudicated

- **D1. A combat unit naming only an age also needs the Military epoch of
  that age.** A: not stated; the unit's `PREQ1` is whatever the column says.
  B: `UnitType::init` lines 732–740 — `if preq[0] ≥ 0 && preq[1] == −1 &&
  is_age(preq[0]) && attack (+0x1e8) ≠ 0 → preq[1] = preq[0] + 0x1c`
  (`0x220 + 0x1c = 0x23c`, `THE_ART_OF_WAR`). **Verdict: B.** Re-read at
  `funcs/UnitType/init@0061ab50.c:731–745`; exactly as B says. This is the
  single most consequential miss: the shipped `unitrules.xml` writes `none`
  in `PREQ1` for most military units and relies on the loader. Landed as
  `UnitTraits::combat` and `TechTree::finalize`.
- **D2. `upgrade` for units is a derived back-link.** A: unit `UPGRADE` is
  empty and `upgrade` unused for units. B: `UnitType::init` 765–787 — a unit
  with a `from`, not a hero, writes itself into `U[from].upgrade` when it has
  no graft, or its predecessor has one, or it is `h`; a grafted unit takes
  its graft's `upgrade` if it has none. **Verdict: B**, confirmed at the same
  lines. `current_upgrade`'s fallback through `upgrade` therefore does reach
  units. Landed in `finalize`.
- **D3. Buildings' `to`, `upgrade` and `where` are derived.** A: `where` of
  a building "—", `upgrade` = `JUMP` copied. B: `BuildType::init` 523–529 —
  `B[from].to = this` (not a hero) and `B[from].upgrade = this` when `this`
  has `build_flags & 4`; 716–734 — `where = (from < 0 ||
  B[from].basic_type() == this) ? −1 : from`; and `upgrade = jump` when
  `jump ≥ 0` on top. **Verdict: B**, confirmed. So a Keep queues at a
  Stockade through `queue_here`'s strict `is(where, 1)`. Landed in `finalize`.
- **D4. `num_preq` for goods.** A: 2 for a unit, 3 for anything else. B:
  `TypeData::num_preq` returns 1, the unit/good/bonus override 2, the
  build/tech override 3 (COMDAT-folded addresses named in `rise_z.map`).
  **Verdict: B.** Harmless for shipped data (a good's third slot is `none`)
  and landed anyway.
- **D5. `lose_tech` on a building.** A: clears the bit. B: the function has
  two arms — unit types, and tech types — and **does nothing to any other
  kind's bit**. **Verdict: B**, re-read at `funcs/Leader/lose_tech@006d2850.c`
  (`if (is_unit_type == 0) { if (is_tech_type != 0) { … } } else { … }`).
  Landed.
- **D6. Gaining a government writes `LeaderData::gov`.** A: not stated. B:
  `this->field_0x14 = t` in the `is_gov_type` arm, and a Capitalism
  (`is(GOV_CAPITALISM, 0)`) gained after frame 0 adds `CAPITALISM_OIL_GIFT`
  (500) to the oil bucket. **Verdict: B**, confirmed at line 1036. Landed as
  `PlayerTech::gov`; the oil gift is economy's.
- **D7. The Tech Race victory.** A: "if `epochs` is now 28, `victory(3)`".
  B: the normal-game check is in the **age** arm — `victory == 9 && !CtW
  semaphore && ages == ending_technology → victory(3)` — and the 28-epoch
  check is the Conquer-the-World variant in the epoch arm. **Verdict: B**,
  confirmed at lines 1242–1247 and 1279. Landed: `Setup::tech_race` and
  `Gained::TechRaceWon` on the ending age.
- **D8. Unit and building gains stop early.** A: listed the cascades as if
  general. B: a unit type `goto`s the epilogue after its own arm, and
  everything that is not a tech type returns before the tech arm — so
  neither units nor buildings run the cascades or the free-tech blocks.
  **Verdict: B** (the implementation already returned early; the document
  did not say so). Landed in the document.
- **D9. The unit-line free blocks are a different shape.** A: one common
  shape. B: Lakota, Iroquois, Indians and Korean-militia blocks match "one
  slot is the tech just gained and the other is owned" rather than
  `has_preq`; the Statue of Liberty block uses `type_eligible(c, 0)` and
  grafts the compared prerequisite. **Verdict: B.** Landed as
  `Shape::TwoPreq`; the Liberty variant is recorded, not implemented.
- **D10. `Build::finished` and non-global buildings.** A: "research
  completes through `gain_tech`". B: a building type without `build_flags &
  4` converts only the building that finished it (`set_type`) and never
  reaches `gain_tech`; an owned unit type trains; everything else goes
  through `gain_tech(t, x, y, 1, 1)`. **Verdict: B.** Landed in the document.
- **D11. `is_list`.** A: open whether it differs from the lineage walk. Both
  readers left it open; the adjudicator read `ObjectType::init_is_list
  @00661dd0`: it fills `is_list` and `is_strict_list` by evaluating `is_slow`
  over every TypeIndex once. So `is_list` **is** the cached closure. Closed.
- **D12. `Types::finalize_grafting`.** B: unique units' grafts have their
  `tribe_mask` rewritten (the graft loses the unique unit's nations, or gains
  them under "No Unique Units"; barbarian tribes always get the graft).
  A: not read. **Verdict: B.** Recorded in the document, not implemented —
  it needs the tribe roster's barbarian flags and the lobby flag at load time.
- **D13. Tribe ids.** A: inferred from the constant names. B (state reader):
  `Tribe::parse`'s switch. **Verdict: established**, not a disagreement.
