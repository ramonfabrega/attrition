## Part 1 — Disagreements (A asserts X, B asserts Y, or A asserts X and B found no evidence)

### D1. Where caravans pay. — **B right**
- **A**: calc_gather step 6 is "Every idle merchant *and caravan*, via `Unit::do_gather`";
  "Merchants and caravans ... Unit::do_gather on an idle merchant ... unread".
  `city_rates()` has no caravan term.
- **B**: caravans are not in calc_gather at all. Each city keeps `trade_val` (CityData +0x52,
  a `short`), recomputed by `City::compute_trade` when a route starts/ends, and
  `calc_city_resources` adds it to wealth first thing. calc_gather's unit loop is only
  Fishermen (0x13d) and `is_merchant` units with `order_type == NONE`.
- **Evidence**: `Leader/calc_gather@006ceee0` unit loop: `(**(vtbl+0xb8))(0x13d,0) != 0 ||
  UnitData::is_merchant(...)` and `UnitData::order_type(...) == NONE` → `Unit::do_gather`.
  `LeaderData/calc_city_resources@006d5530`: `if (-1 < param_5) param_1[2] += *(short*)(city + 0x52)`
  before the building walk. `City/compute_trade@00739640`: `trade_val += (short)((v*0x10)/2)`
  for each caravan link with flag &4 and both endpoint cities active (+4 &1); change → leader
  flag `|= 0x2000000`. `Caravan/trade_value@0073d9d0`: `v = get_trade_value(a)+get_trade_value(b)`;

  Spice `(SPICE_CARAVAN_INCOME+100)*v/100`. `Caravan/distance@0073d300`: 0 if `< W/4`, 1 if `< W/2`,
  2 if `< 4W/5`, else 3 (W = `*(int*)GameAccess::world`). `CityData/get_trade_value@007363f0`:
  `num_buildings + {Large 0x19f: 2, Major 0x1a0 / Forbidden 0x213: 4, else 0}`.
- **Impact**: A's doc misplaces caravans; the implementation is missing a wealth term per city
  (`trade_val`, in sixteenths). Not a wrong number today (A scoped it out) but the doc's
  placement in step 6 would send an implementer to the wrong function.

## Part 3 — Doubly confirmed (A and B agree; I re-read the expression)

- Frame order: `Leaders::process_all` first in `Game::do_frame`; `Objects::process_all` later.
- `Leader::gather`: copy `resources` → `calc_gather` (lazy) → store → rare merge →
  `support[0..5] = 0` → `calc_resource_caps` (every frame) → `do_gather` (every frame).
  (`@006ce280`.)
- Cadence: not dirty → `frame >= gather_stamp+300 && (frame + who*8) % 256 == 0` ⇒ 512-frame
  period; dirty → `frame == 0 || (who+frame) % 8 == 0`; completion clears `0x2000000` and stamps.
- Rate unit: sixteenths per `GATHER_RATE` (450) frames; `denom = GATHER_RATE*16 = 7200`.
- `PEASANT_RATE`, `OIL_RATE`, `SCHOLAR_RATE` load at ×256 via `get_fraction(...,0x100)`
  (`Constants/init@00569a90:857/866/881`); consumers `>>8`. `GATHER_RATE`, `CITY_GATHER`,
  `BASIC_GATHER`, `COMMERCE_CAP`, percentages: plain.
- Assembly: `BASIC_GATHER<<4`; Lakota/Americans flat terms; cities; oil wells; outside
  woodcutters/mines; idle fishermen/merchants; refinery `((n*REFINERY_BONUS+100)*oil)/100`;
  Capitalism `+CAPITALISM_OIL_PROD*16`; Coffee ×(COFFEE_INCOME_BONUS+100)/100 all six;
  territory tax `(territory*TERRITORY_TAXES[lvl]*16)/land_size` (guarded `land_size != 0`);
  `calc_resource_bonuses`; clear dirty + stamp; obsolete `r[to] += (r[T]*rate)>>8; r[T]=0`.
- City: building chain via `+8`/`+0x74`, `is_gather_type`, not 0x1a5/0x1a6, same city;
  `CITY_GATHER[T]*16`; Romans wealth, Germans food/timber/metal(if avail);
  `get_taxes()*16` = `VILLAGE_TAXES + n*BUILDING_TAXES + [MARKET_TAXES] + [TEMPLE_TAXES]`;
  `get_literacy()*16` = `VILLAGE_LITERACY + [UNIVERSITY_LITERACY] + [LIBRARY_LITERACY]`.
- Enhancer: `enhancer_amount(T, base) = (pct+100)*base/100`, wealth/knowledge → 0; applied to
  the *per-gatherer* value (`per = per*enh/100`) before `× gatherers`, truncating there.
- University per-scholar: `(SCHOLAR_RATE[get_university()-1]*16)>>8`, `get_university` 1..6.
- Caps: `COMMERCE_CAP[epoch[2]]` (Commerce level, `encrypt+0xf0 ^ 0x63187`), knowledge slot 3
  = 999 unconditionally, VR = 999, clamp `[0,999]`, `<<4`, seven slots with the seventh unread.
- `do_gather`: `inc = resources - support + base_rate`; `< 0` → shown, not paid; cap clamp with
  `over_cap = 1 + (cap > 0x3e6f)`; `income` captured before handicap; handicap
  `((h+100)*inc)/100`; ×3/4 or ÷2 knowledge; ×3/2 fast; ×ai_speed; `whole = inc/7200;
  leftover += inc%7200; while (leftover >= 7200) {whole++; leftover -= 7200}`; `bucket += whole;
  collected += whole`. The six handicap literals −35/−15/−7/0/+25/+50.
- `LeaderDataEncrypt` offsets and XOR masks (bucket 0x8221, leftover 0x3421, resource_cap
  0x1281, over_cap 0x8932, resources 0x872, support 0x26076, income 0x90236).
- `support` is dead on the income path (zeroed in `gather`, `calc_support` writes zeros).
- Implementation nuance (not a disagreement): `pay()` tests `cap > 999*16-16 = 15968` where
  the original tests `> 15983`; equivalent because every cap is `c<<4`, so the only multiple of
  16 above 15968 is 15984.
