# Natural suspended searches through ordinary orders

## Result and scope

Two independent launches of the same seeded Great Lakes scenario produced
2,314 A* returns, including **1,787 suspensions**, in frames 0–1,400. The first
suspension is frame 223, three frames after the first group order. The previous
passive 8,000-frame census found none. This is a coverage improvement in the
original-game instrument; neither simulation headline floor moves.

Both runs match on all 1,401 observed frame/seed pairs, the spawned captain
roster, ten order/target receipts, the ordered sequence of A* frame/step/anti/
return values, and all 64 captured metadata shapes. Metadata comparison removes
process addresses but preserves nullness, lengths, capacities, limits, saving
and the repeated-owner relation. These projections do **not** establish full
simulation-state parity, absence of instrumentation effects, or Rust resumption.

All suspensions use step 48 and anti=0. The remaining returns are 236 failures
and 263 successes at step 48, five successes at 192 and 23 successes at 768.
The collector reaches its explicit 64-event cap at frame 264; later suspensions
are counted but their graphs are unmeasured. No read-failure or scenario-failure
receipt appears. Unlike the preceding passive run, this exercises the actual
metadata reader in the live original.

## Reproducible scenario

Stage with `live_session.py stage INSTALL OUTPUT PROFILE --end-frame 1400
--fast-forward`. Write `congestion_probe.py schedule` to OUTPUT/rontrace.cmd.
Build with `TRACER_DEFS='-DRON_CONGESTION_PROBE -DRON_SEARCH_CENSUS -Werror'`,
bind the images with `replay_capsule.py bind`, and use the normal Wine/lobby
path. The command script invokes ffwd at frame 37, 32 original `add hoplite`
commands at 150–181, and quit at 1,400. Its tile arguments reuse the region
already exercised by the capture manifest; placement is measured by the roster,
not inferred from the arguments.

The driver snapshots active owner-zero registry IDs/UIDs at frame 149. At 210
it selects newly appearing captains, alternates them into two groups and records
their actual positions. This run has 16 captains in each group and measured
centroid (3207, 32794). At 220/221 and every 200 frames through 1020/1021, the
original MoveTo issuer sends them toward opposite points 1,536 coordinate units
from that centroid, reversing each time. Each package grows from 10 to 67 bytes.
All 34 scheduled console commands return success. The native command logger
records each MoveTo at the issued target on the following frame. All 29 logged
frame bodies match between launches: 18 early detailed frames, ten command-only
frames and the closing unit dump at 1,401 (`logged-state-repeat.json`). This is
not detailed state coverage of the intervening frames. A console return alone would
not prove the spawns; the independent roster receipts establish 32 captains.

No unit coordinates, repath counter, pathfinder limit or saved-search field is
written directly. Orders enter the original package and normal turn pump.
Search pressure is generated by the resulting scenario. `docs/PATHFINDER.md`
§8 and `docs/COLLISION.md` §6 explain why congestion is a useful target: native
collision repaths lower the budget. The first measured limit is 125 and saving
is 1; this run does not separately sample the repath counter.

## Bounds, evidence and checks

`Units::make_valid@0061a960` establishes owner-zero registry high-water length
at units+4, capacity at +8, and pointer storage at +0x10. The driver checks
length ≤512, length ≤capacity ≤32768 and reads through checked
ReadProcessMemory calls. Existing PDB-backed command-probe fields supply active,
owner, ID, UID, position and captain status. Every issued group revalidates the
current captain ID/UID. A fresh group reserves 3+2*n bytes in
`CommandPackage::add_group@0094bb60`; the MoveTo payload is 22 bytes in
`CommandManager::issue_move_to@00941720`. The driver additionally reserves four
padding bytes, checks the existing package length and validates the issuer's
prologue. It refuses overflow, short reads, stale identity and wrong ownership.
These are bounded reads, not a general registry reader or allocator adapter.
A final host-tested guard refuses a second match in the same process before
retained roster counts can be reused. It was added after the two live captures;
the captured DLL identity remains in each image binding, and the final DLL is
link-checked separately. The successful first-match path is unchanged.

Across the first 64 events, maximum lengths are open 138, refs 138, closed 289,
valid 536, block 10. The largest **simultaneous** sum is 1,059, not the sum of
these independent maxima. The first event's lengths are 46/46/21/86/3 (202 total).
This makes that first event a concrete next graph-capture target. A cap must
still reject excessive nodes, cycles, invalid pointers and missing payloads;
header counts alone do not prove graph completeness or ownership. The earlier
synthetic cleanup fixture's 31-node bound is insufficient for these witnesses.

The host C fixture exercises the exact driver with authored registry memory:
roster selection, short reads, invalid length/capacity, missing baseline, excess
captains, owner filtering and recycled UID refusal. It never calls the original
issuer; the two live runs exercise that path. Five Python tests reject every
missing scenario receipt, partial frames, explicit failures, duplicate identities,
rejected packages and altered targets. Projection tests also detect changed RNG
seeds and container lengths while accepting relocated process addresses. Existing census tests cover metadata
framing and the 64-event cap. Default tracer preprocessing is checked unchanged;
the new macro requires census and excludes the single-unit command experiment.

`/tmp/attrition-congestion` and `/tmp/attrition-congestion-repeat`, each with
image binding and trace. `repeat-report.json` in the first directory records
the comparison; `census-report.json` records the first run's raw metadata.

closed normally and all five backed-up profile files were restored and compared
byte for byte.
